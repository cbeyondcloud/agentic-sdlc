# SP17 GitHub Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal (M1-58):** A finished run's branch is pushed, a pull request is opened whose body links the run and its handoffs (M1-45's `pr_body` and trailers, reused), and CI on that pull request is read or watched until it settles, following Zyroflo's `release.py` flow (push through the wall, open, watch the real CI; never merge). `agentic init --repo` opens its pull request the same way instead of only printing the compare URL (DF-183). The GitHub REST API is called with httpx2 and a token from `agentic.auth.Credentials` (environment, then the OS keyring). GitHub Enterprise base URLs work. The `gh` CLI is never needed. The hosting provider sits behind a small protocol, so GitLab or Azure DevOps can be added later without engine changes. Also in scope: DF-166 (open the PR with `pr_body` and `proposals()`, links to the control plane when one is set), DF-173 (the `Agentic-Approved-By` trailer must not cite an approval that a later rejection superseded) and DF-174 (the `Agentic-Handoff` trailer gives a repo-relative path).

**Architecture:**
- **New package `agentic.hosting`** (core; it never imports `sdlc_commons` or Zyroflo; no vendor names in `base.py`):
  - `base.py`: `HostingProvider` protocol, `RepoRef`, `PullRequest`, `CheckRun`, `HostingError`, `parse_remote(url)`.
  - `git.py`: `remote_url`, `push_branch` (plain `git push` of one branch, never forced, no terminal prompt, output scrubbed of URL credentials) and `rev_parse`.
  - `github.py`: `GitHubHost`, the GitHub REST adapter over `httpx2.Client`. `api_url_for(host, configured)` gives `https://api.github.com` for github.com and `https://<host>/api/v3` (or the configured URL) for Enterprise. It refuses plain http except to a loopback host. Pagination follows `Link: next` only on the API's own origin. Check runs and commit statuses are both read.
- **Zyroflo reuse through `sdlc_commons.release`**: `ci_verdict(rows)` translates REST check rows with Zyroflo's `release._rest_bucket` and judges them with `release.verdict`. That gives five answers (green, red, pending, none, unknown), and only green passes. The push wall is the existing `sdlc_commons.guards.Guard.push` (Zyroflo `policy.push_target`).
- **CLI wiring:**
  - `agentic_cli/hosting.py`: the host registry. It holds github.com built in, plus `git_hosts:` from `~/.agentic/config.yaml` (Enterprise: `kind`, `api_url`, `credential`). It maps a provider kind to its factory and credential name, and `connect(repo)` returns the provider and repo for `origin`. A new provider is one entry here plus one adapter module.
  - `agentic_cli/publishing.py`: `publish_run` and `watch_ci`. `publish_run` checks the wall for each run tree, then pushes, then opens or updates the PR with a redacted `pr_body`, and records `pr.json` in the run folder. `watch_ci` polls until the checks settle, with a grace period before reporting none, and records `ci.json`.
  - The engine actions are `github.open_pr` (the spec's name) and `open_pr` (whatever host `origin` is). `Runtime` builds them per workspace; the engine is unchanged.
  - The new `agentic pr` group has `pr open RUN` and `pr checks RUN [--watch]`.
  - `agentic init --repo` pushes `agentic/init` and opens its PR. `--no-pr` keeps the old behaviour. With no token or no known host it warns and prints the manual steps.
  - `agentic login --for github` stores the token.

**Tech Stack:** Python 3.12, httpx2 (already a core dependency), truststore through `agentic.transport.ssl_context`, `keyring` through `Credentials`, Zyroflo `tools.sdlc.release` (pinned rev) through commons. Tests use pytest, `httpx2.MockTransport` for the adapter units, a stdlib `ThreadingHTTPServer` fake GitHub, and a local bare git remote (via `remote.origin.pushurl`) for the contract tests. No new dependency.

**Spec:** §6 (`action: github.open_pr`), §14.5 (trailers, PR body), §16 (GitHub v1; "PR creation and CI watch reuse Zyroflo's flow"; other platforms behind the same interfaces), §24 (init --repo opens a normal PR), §15 (corporate proxy/CA).

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| GitHub REST client | httpx2 directly (D36), 6 endpoints | PyGithub: LGPL-3.0, not on the allow-list. githubkit (MIT): a large generated client for 6 calls, which is a heavy dependency. ghapi (Apache-2.0): pulls in fastcore and builds calls dynamically |
| CI verdict vocabulary and judgement | Zyroflo `release.verdict`, `release._rest_bucket` (via `sdlc_commons.release`) | Zyroflo's `gh` calls (`_gh`, `check_rows`, `open_pr`): `gh` must not be required. Zyroflo's `repo_of`: it refuses Enterprise hosts |
| Push wall | Zyroflo `policy.push_target` via `sdlc_commons.guards.Guard.push` | Zyroflo `release.push`: it requires the run folder committed on the branch (`.sdlc/runs`), but our run folders are git-ignored; the ledger summary on the branch is a later row |
| Credentials | `agentic.auth.Credentials` (env, then keyring) | — |
| Fake GitHub for tests | stdlib `http.server` | — |

## Global Constraints

- **The token never leaves memory:**
  - it is not in a repr, an exception message, a log record, `pr.json`, `ci.json`, the ledger or stdout/stderr;
  - every error text from the API or from git is scrubbed of the token and of URL userinfo;
  - the token goes only to the configured API origin: https, or http to a loopback host for tests. Redirects are not followed, and a pagination link to another origin is refused.
- **Pushing uses the person's own git credentials** (credential helper or SSH key), as Zyroflo's `push` does. The API token is never put in a git URL or a command line. `GIT_TERMINAL_PROMPT=0`, so a push inside a run never hangs on a prompt.
- **Never merge.** No code path calls a merge endpoint. A test asserts that no `/merge` request is made.
- **The run branch is pushed only through the wall** (`Guard.push`: the approved remote and the run's own `sdlc/<run>` branch). A component without a tree (in place, DF-62) is refused with a reason. The `init --repo` branch is the owner's own action and needs no run wall.
- **Provider-agnostic:** `agentic/hosting/base.py`, the engine and the CLI flags name no vendor. GitHub appears only in `github.py`, the host registry and the spec's action name.
- **Windows and macOS:** git is called with argument lists (never a shell), paths are `Path`, JSON files are written with LF, and tests run on both.
- **Formatting, CI and records:**
  - never `# fmt: skip` or `# fmt: off`; ruff line length 100;
  - check pytest's exit code directly;
  - `uv run python scripts/check.py --all` must be green;
  - TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.

## Review Focus

1. **Token leakage.** Run the whole publish → checks flow with a distinctive token while the fake server returns errors that echo the request. Neither the token nor a userinfo URL appears in output, logs, the run folder or the ledger. Test: Task 6 `test_the_token_never_reaches_output_logs_or_the_run_folder`, Task 2 `test_errors_and_repr_never_hold_the_token`.
2. **The token goes nowhere but the API origin.** Plain http to a non-loopback host is refused, and a `Link: next` to another host is refused. Test: Task 2 `test_plain_http_is_refused_except_loopback`, `test_pagination_never_leaves_the_api_origin`.
3. **Not green is never green.** No checks gives `none` (after the grace period), a still-running check gives `pending`, a skipped check is not a pass, and a failed commit status is red. Test: Task 3, Task 6 `test_watch_reports_none_after_the_grace_period`.
4. **The push wall.** A branch that is not the run's own, or a remote that is not approved, is refused before anything leaves the machine. Test: Task 6 `test_the_push_wall_refuses_before_pushing`.
5. **DF-173.** A step redone after a rejection does not cite the approval of the work the rejection threw away. Test: Task 4 `test_a_redone_step_does_not_cite_a_superseded_approval`.
6. **Idempotent publish.** Publishing again updates the existing PR body instead of opening a second PR. Test: Task 6 `test_publishing_again_updates_the_same_pull_request`.

### Task 1: Hosting protocol, remote parsing, git push (core)

**Files:**
- Create: `core/src/agentic/hosting/__init__.py`, `base.py`, `git.py`
- Test: `core/tests/hosting/test_hosting_remote.py`, `core/tests/hosting/test_hosting_git.py`

**Interfaces:**
- `parse_remote(url) -> RepoRef(host, owner, name)` handles https, ssh and scp forms, a port, and userinfo, which is dropped. A local path or a URL with no owner is a `HostingError`. The host is lower case. The owner may hold `/` (nested groups).
- `push_branch(where, remote, branch, *, timeout=600, secrets=())` runs `git push -u <remote> refs/heads/<b>:refs/heads/<b>`, never forced. A remote or branch that starts with `-` is refused. On failure the last lines of git's output are scrubbed.

**TDD steps:**
- [ ] Write the remote parsing tests (forms, port, userinfo dropped, local path refused) and see them fail.
- [ ] Write the push tests against a bare remote: the branch arrives; a non-fast-forward is refused and not forced; the userinfo in a failing URL is scrubbed. See them fail, implement, see them pass, and commit.

### Task 2: GitHub REST adapter (core)

**Files:**
- Create: `core/src/agentic/hosting/github.py`
- Test: `core/tests/hosting/test_github_host.py` (httpx2.MockTransport)

**Interfaces:**
- `GitHubHost(api_url, token, *, network=None, timeout=30, transport=None)` provides `default_branch`, `find_pull_request`, `open_pull_request`, `update_pull_request` and `checks`.
- `api_url_for(host, configured=None)`.

**Behaviour:**
- headers `Authorization: Bearer`, `Accept: application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28`;
- a 422 "already exists" on create falls back to find;
- `checks` merges check runs (paginated) with combined commit statuses, mapping `error` and `failure` to conclusion `failure` and `pending` to status `pending`;
- 401, 403 and 404 give actionable `HostingError`s.

**TDD steps:**
