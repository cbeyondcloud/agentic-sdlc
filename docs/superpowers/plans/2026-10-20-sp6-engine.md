# SP6 Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run a pipeline end to end on one machine. The engine checks a pipeline before any spend, runs its steps in order (`when` conditions, loops with `until` and `max_iterations`), pins and gates each handoff for human approval, pauses for a person on limits, timeouts and invalid output, and resumes after a crash from the last completed step.

**Architecture:** A new `agentic.engine` package in `core`:
- `expressions.py`: CEL conditions (spike S13).
- `state.py`: `run.json`, written atomically, with the run's cursor and history.
- `engine.py`: the state machine that walks a `PipelineDefinition`.
- `gates.py`: approve / reject / edit, regimes and four-eyes.
- `preflight.py`: a readable report before any spend.
- `factory.py`: builds a step's runner from the resolved agent.

The engine never imports `sdlc_commons` or Zyroflo. It takes two small protocols, `RunRecorder` (events and artefacts) and `GateLedger` (approval entries and gate state). The production implementations live in `sdlc_commons`: `RunLedger` (exists), and a new `gates.py` adapter over Zyroflo's `approve.gate_state` / `policy.self_approval` / `policy.PRESETS`, plus a new generic `approve.append_entry` added to Zyroflo by a small, backward-compatible PR (Z6).

**Tech Stack:** Python 3.12; cel-python 0.5.0 (Apache-2.0, S13); Pydantic v2; the existing `agentic.agents` (runner, contract), `agentic.handoffs`, `agentic.policy`, `agentic.transport` (budget), `sdlc_commons` (ledger, gates), Zyroflo pinned (`approve`, `policy`, `events`, `state`).

**Spec:** `docs/superpowers/specs/2026-10-16-agentic-sdlc-design.md`:
- §6 pipelines, `when`/`until`; §6.1 gate model: regimes, digest pinning.
- §7.3 run ledger: the engine refuses to pass a gate without a valid approval entry.
- §8.2 preflight; §8.3 execution: state machine, `run.json` atomic, each step a checkpoint, gates persist and exit.
- §8.4 limits: a step or run limit hit pauses for a human.
- §8.5 the pipeline-level oscillation check; §8.7 failure handling; §12 / §23 approvals.
- D33 pipelines admin-controlled; D34 Zyroflo via adapters; D35 agent types; D37 handoff templates.

Spikes: `docs/spikes/S13-expression-evaluator.md`; Zyroflo survey (2026-10-20) summarised under Reuse below.

Master plan rows: M1-21 … M1-26. DEFERRED.md items: DF-05, DF-06, DF-09, DF-11, DF-12, DF-18, DF-22, DF-26, DF-28, DF-29, DF-34, DF-38, DF-39, DF-41, DF-42, DF-43, DF-44.

## Global Constraints

- Core does not import `sdlc_commons` or Zyroflo; the engine takes protocols and the CLI or tests wire the commons implementations (D34). Zyroflo is changed only by a PR the owner merges.
- `run.json` lives in the run folder `.agentic/local/runs/<run-id>/`, next to Zyroflo's `events.jsonl`, `approvals.jsonl` and `state.json`. Never write Zyroflo's file names. Every artefact an approval pins (handoffs) is written **inside the run folder**.
- `run.json` is written atomically: write a temporary file in the same folder, `fsync`, then `os.replace` (§8.3). It is UTF-8 with LF line endings.
- Each step is a checkpoint. A step is recorded as completed only after its handoff is written and pinned; a crash before that re-runs the step from its start.
- A step or run limit hit, a timeout, an invalid answer after its retry, a stuck agent or an exhausted loop **pauses the run for a human**; nothing is decided silently (§8.4, §8.7).
- The engine never advances past a gate without `GateLedger.gate_state(gate)` returning satisfied (§7.3).
- Regimes (§6.1):
  - **solo**: the starter may approve.
  - **team**: the gate's `approver_role` is required, and four-eyes applies when the gate sets `four_eyes: true`.
  - **regulated**: four-eyes is mandatory. Signed approvals and required evidence are E2-03; record a DEFERRED item.
  - `block_on` comes from the regime.
- Standalone mode (M1) has no RBAC: the `Authorizer` grants every role. Org RBAC is M2-03.
- Money is `Decimal`. Policy floats convert through `str` (DF-26).
- Tests make no network or model calls (FunctionModel). `uv run python scripts/check.py --all` (Windows + Linux) is the gate. Never add `# fmt: skip`.

## Review Focus

1. **The process dies while `run.json` is being written** (laptop sleep, Ctrl-C). The previous `run.json` is intact and `resume` continues from the last completed step. Test in Task 2.
2. **The process dies in the middle of an agent step**, after spending but before the handoff is recorded. Resume re-runs that step from its start, and the money already spent still counts against the step and run budgets. Test in Task 4.
3. **A handoff changes on disk after its gate was approved.** The engine refuses to advance and re-opens the gate, because the approval's digest no longer matches. Test in Task 5.
4. **A person edits a handoff at a gate and breaks its front matter.** The error is precise, approval is refused, and the original file is untouched. Test in Task 5.
5. **A `when` or `until` names a field that no earlier step produced.** The run pauses for a person, with the expression and the reason. It never crashes, and it never silently treats the condition as true or false. Test in Task 4.

- Produces:
  - `class RunRecorder(Protocol)` (implemented by `sdlc_commons.ledger.RunLedger`):
    - `run_dir: Path`
    - `record(event: str, step: str, **fields) -> None`
    - `write_artifact(rel: str, text: str) -> str` (returns the digest)
    - `digest(rel: str) -> str`
  - `class GateLedger(Protocol)`: `record`, `state` and `waiting`, as in Task 3.
  - `class StepRunnerFactory(Protocol)`: `def __call__(self, step: StepContext) -> AgentRunner`.
  - `StepContext(run_id, step: str, iteration: int, agent: ResolvedAgent, budget: BudgetSlice, contract: OutputContract | None)`, frozen.
  - `class Clock(Protocol)`: `def now(self) -> datetime`, timezone-aware.
  - `Engine(*, definitions: DefinitionSet, policy: OrgPolicy, context: ResolveContext, store: RunStore, recorder_for: Callable[[str], RunRecorder], gates_for: Callable[[str], GateLedger], runner_factory: StepRunnerFactory, block_on_for: Callable[[str], frozenset[str]], clock: Clock, actions: Mapping[str, Callable[[RunState], str]] = {})`. The same engine object serves any run.
  - Methods:
    - `start(pipeline: str, inputs: dict[str, str], starter: str, run_id: str) -> RunState`: creates the run and advances it.
    - `advance(run_id: str) -> RunState`: runs from the cursor until a gate, a pause, the end, or a failure.
    - `resume(run_id: str, *, extra_minutes: int = 0, decisions: dict[str, bool | str] | None = None) -> RunState`: clears a `pause` (or answers a tool `approval` with `decisions`) and advances.
    - Gate decisions are Task 5.

What `advance` does, in order, for the step at the cursor:
1. **Run timeout** (M1-26): if `max_minutes` is set and `clock.now() - started_at` exceeds it (plus any `extra_minutes` granted), pause with `Pending(kind="pause", id="run-timeout", reason="run time limit <m> min reached")`.
2. **Agent step:**
   - If it has a `when`, evaluate it over `latest` (front-matter fields read from each latest handoff). False records `StepRecord(outcome="skipped")`. An `ExpressionError` pauses with id `condition` and the error text (Review Focus 5).
   - Otherwise resolve the agent. Open a step budget slice from the run ledger with the agent's `budget_usd` (Decimal via `str`, DF-26), and build the contract from `definitions.handoffs.schema(agent.produces)` with `block_on_for(regime)` (DF-43).
   - Emit `step_started`, call the runner, then map the outcome:
     - `completed` → write `handoffs/<step>-<iteration>.md`, digest it, record `latest[kind]`, and emit `step_finished(outcome="completed", artifacts=[rel], cost=...)`.
     - `invalid` → pause with id `invalid-output`. The last text is written to `handoffs/<step>-<iteration>.invalid.md`, the errors go in `reason`, and a person resolves it with a gate edit or reject (Task 5).
     - `stopped` (budget, turns, time, stuck) → pause with id `step-<reason>`. `time` is the step timeout (M1-26).
     - `paused` → `Pending(kind="approval", state_path=..., state_digest=...)`.
     - A raised `LimitHit` (step or run scope) → pause with id `budget` and the limit in `reason`.
   - The step slice is closed in all cases. A `BudgetError` on close (calls still in flight, DF-22) is recorded in `detail` and does not fail the run.
   - After each step, save `run.json` with `budget = ledger.snapshot()`.
3. **Gate:** emit `gate_waiting`, set `Pending(kind="gate", id=<gate>, artefacts=<every handoff written since the previous gate, path → digest>)` and status `awaiting_gate`, then stop.
4. **Loop:**
   - Run its body steps (1–2) in order, with `cursor.loop_iteration` starting at 1.
   - After each full iteration, evaluate `until` over `latest`. True → leave the loop and emit `loop_back`; it is not emitted on exit.
   - **Oscillation** (DF-29): if this iteration's review findings repeat a finding text from the last 2 iterations (`agentic.agents.stuck.oscillation`), treat the loop as exhausted, with reason `oscillating`.
   - At `max_iterations` without `until`: `on_exhausted: gate` → pause as a gate with id `<loop>-exhausted`; `fail` → status `failed` and `run_closed(status="failed")`.
   - Otherwise emit `loop_back(from=<last body step>, to=<first body step>)` and start the next iteration.
5. **Action:** run `actions[name](state)`; the returned text is recorded in `StepRecord.detail`. An unknown action is a preflight error (Task 7); at run time it fails the step.
6. **End:** after the last step, status `completed` and emit `run_closed(status="completed")`.

Each completed or skipped step advances the cursor and saves `run.json` before the next step starts. That is the checkpoint, so a crash re-runs only the step that was in progress (Review Focus 2).

### Task 5 (M1-22): gate decisions — approve, reject, edit; regimes and four-eyes

**Files:**

**Interfaces:**
- Consumes: `RunState`, `Pending` (Task 2); `GateLedger` (Tasks 3–4); `parse_handoff(text, catalog, block_on=)` (SP5).
- Produces:
  - `class Authorizer(Protocol)`: `def holds(self, user: str, role: str) -> bool`. `StandaloneAuthorizer()` grants every role (M1 has no RBAC).
  - `GateRefused(Exception)`: one readable reason.
  - `Decision = Approve(approver: str, notes: str = "") | Reject(approver: str, feedback: str) | Edit(approver: str, path: str, text: str, notes: str = "")`. `Edit` replaces one pending artefact, then approves.
  - `Engine.decide(run_id: str, decision: Decision, *, authorizer: Authorizer, self_approval: Callable[[str, str], str | None]) -> RunState`.

Rules for `decide`, applied to the run's `pending` gate (or to an `invalid-output` or exhausted-loop pause, which a person settles the same way):
1. **No gate waiting** → `GateRefused("run <id> is not waiting at a gate")`.
2. **Role.** Under team and regulated, `authorizer.holds(approver, gate.approver_role)` is required. Under solo the starter may approve, and anyone else still needs the role.
3. **Four-eyes.** Under regulated, or a gate with `four_eyes: true` under team, `self_approval(approver, state.starter)` must be None (`sdlc_commons.gates.self_approval_refusal`).
4. **Edit:**
   - The path must be one of `pending.artefacts`.
   - Normalise CRLF (DF-39), then `parse_handoff(text, definitions.handoffs, block_on=block_on_for(regime))` (DF-38, DF-42).
   - On error → `GateRefused` with every error and line; the original file is untouched (Review Focus 4).
   - On success, write the edited text to `<path>.edited-<n>.md` (the original is kept for the record and the learning loop), and repin: `pending.artefacts` and `latest` now point at the edited file.
   - Then continue as Approve.
5. **Approve.**
   - Before recording, every pinned artefact's current digest must equal the pinned one. A mismatch re-opens the gate: refuse with the changed paths, re-read the digests and wait for a new decision (Review Focus 3).
   - Record the decision with `gates.record(gate, "approve", approver, pending.artefacts, step=<previous step>)`.
   - Advance only when `gates.state(gate)` is satisfied.
   - Clear `pending`, step the cursor past the gate, and `advance`.
   - For an `invalid-output` pause, approving an edit records the edited text as the step's completed handoff.
6. **Reject.**
   - Record the decision with `gates.record(gate, "reject", ...)` and store `feedback[target] = feedback`.
   - The target is the gate's `on_reject`, else the nearest agent step before the gate. For an `invalid-output` pause it is that step; for an exhausted loop it is the loop's first step, with the counter reset.
   - Move the cursor to the target and `advance`; the target's next prompt carries the feedback.
7. **Advancing never reads an approval as valid without `gates.state`:** `advance` re-checks the gate before passing it, so drift after approval re-opens it (Review Focus 3).

**DF-41: proposed default, for the owner to confirm at plan review.** An agent may not mark a finding at a blocking severity `accepted`.
- `finalise_handoff` (the agent path) refuses it with `findings[<i>]: only a person can accept a finding at a blocking severity (<severity>)`.
- `parse_handoff` (the person path, at a gate) allows it, and the gate entry records who accepted it.
