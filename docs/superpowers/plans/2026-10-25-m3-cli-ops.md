# M3 CLI Operations Implementation Plan (M3-08, M3-09, M3-10)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three operations features for a 1000-seat rollout on Windows and macOS laptops:

- **M3-08 `agentic gc`** prunes finished run folders and run worktrees by age, never a paused or running run, never a run whose ledger the control plane has not received (org mode), and survives Windows file locking. `agentic status` warns when this repository's local data exceeds a cap.
- **M3-09 `agentic doctor`** reports every prerequisite `agentic init` checks plus runtime health, each with a fix and an exit code. **`agentic support-bundle`** writes a redacted zip for the platform team. Doctor also checks that the org policy repo's default branch requires code-owner review (D33).
- **M3-10 sandbox resource limits** per agent command, from policy: CPU time, memory, file size and process count. Enforced on Linux and macOS, best effort (Job Object limits) on native Windows, each documented.

**Architecture:**

- **Core** (imports neither `sdlc_commons` nor `agentic_cli`):
  - `agentic.policy.model`:
    - `LocalDataPolicy` (`limits.yaml` `local:`): `gc_after_days = 14`, `disk_cap_gb = 20`.
    - `ResourceLimits` (`org.yaml` `sandbox.limits:`): `cpu_seconds`, `memory_mb`, `max_file_mb`, `processes`. Each is `None` (no limit) by default, so existing policy repos keep working.
  - `agentic.telemetry.sinks.queued(run_dir, sink_name)`: how many ledger events a sink has not taken. The same arithmetic as `ForwardingRecorder.pending`, without a sink object.
  - `agentic.sandbox.limits`:
    - the POSIX launcher: `python -I -c <setrlimit; execvp>` around the innermost command, inside `srt`;
    - the tree watchdog: processes and resident memory, polled;
    - the Windows Job Object limits, passed to `ProcessTree.adopt`.
  - `run_process(..., limits=)`, `SrtSandbox(limits=)` and `LocalProcessSandbox(limits=)` apply them. `ShellResult.limited` names the limit that stopped a command.
  - `agentic.transport.client.probe_gateway`: verdict, served model names and the server's `Date`, in one `GET /v1/models` call.
  - `agentic.hosting.github.GitHubHost.branch_protection(repo, branch)` returns a `BranchProtection`. It reads classic protection first, then rulesets.
- **Commons:** `RunWorktrees.root()`, the folder holding a run's trees (public; it was `_trees_root`).
- **CLI:**
  - `agentic_cli.housekeeping`:
    - `plan_gc` (what would go, and why each other finished run is kept);
    - `collect` (removes trees, then renames the run folder aside, then deletes it);
    - `local_usage` (bounded walk);
    - `gc_settings` (precedence: flag > user config `gc:` > policy `local:` > built-in).
  - `commands/gc.py`: `agentic gc [--older-than DAYS] [--dry-run]`. `commands/runs.py` `status` gets the cap warning.
  - `agentic_cli.doctor`: `Check` items (`ok` / `fail` / `warn` / `info` / `skip`), each with a fix.
  - `agentic_cli.support_bundle`: assembles, redacts, screens and verifies. `commands/doctor.py` registers `doctor` and `support-bundle`.
  - `wiring.py` passes `policy.sandbox.limits` to every sandbox it builds.

**Tech Stack:** Python 3.12 stdlib only: `shutil`, `zipfile`, `os.scandir`, `resource`, and `ctypes` for kernel32. No new dependency.

**Spec:** §8.1 (init prerequisites), §8.3 (run folder), §9.2 (worktrees, sandbox), §13 (credentials), §14.6 (OR-01: nothing is deleted *automatically*; gc is a manual command), §20 (support: doctor and support-bundle), D33, D38. Master plan rows M3-08, M3-09, M3-10.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Process memory and process counts | `/proc` on Linux, `ps` on macOS (as `agentic.backends.processes` already does) | `psutil` (BSD-3): a native extension, and no unsigned native binaries may run on Windows laptops. Windows uses Job Objects instead |
| cgroups v2 limits | (none) | `systemd-run --user --scope`, or a delegated cgroup: not available inside srt's bubblewrap, inside a Docker CI container, or on macOS. Recorded as a ruling; DF candidate for laptops that have it |
| Clock skew | the HTTP `Date` header of the control plane or gateway answer doctor already makes | `ntplib` (MIT): UDP 123 is blocked on most corporate networks; one more dependency |
| Support bundle redaction | `sdlc_commons.redaction.redactor` (Zyroflo masking) and `PublishGuard` (M2-49 publish scan, masking) | a new redactor: there must be one definition of a secret |
| Branch protection | the existing `GitHubHost` (httpx2) | PyGithub (LGPL): licence, and a second GitHub client |
| Windows-safe tree deletion | the `policy_source._writable_and_retry` pattern (read-only git objects), with rename-aside first | `send2trash` (BSD): moves to the user's recycle bin, so nothing is freed |

## Global Constraints

- **Only finished runs are collected.** A finished run is `completed`, `failed`, `stopped` or `killed` (`engine.TERMINAL`). A `running`, `paused` or `awaiting_gate` run is never touched, and neither is an unreadable `run.json` (kept, with the reason).
- **Org mode: queued events survive.** With `org` set in the user config, a run whose ledger has events the `control-plane` sink cursor has not passed is kept, with "N events not yet delivered: run `agentic sync`". This includes a run the publish scan held back. In org mode with no control plane configured, every run is kept: no central copy exists (needs decision).
- **Trees before folders.** A run's trees are removed through Zyroflo (`RunWorktrees.remove`, never forced). Uncommitted work, or a tree in use, keeps the whole run, so its record stays consistent. Branches are kept: a pull request may name them. `git worktree prune` runs at the end.
- **Windows locking.** The run folder is renamed to `<runs>/.gc-<run>-<pid>` before deletion. A refused rename (a file held open) keeps the run and says so. Deletion clears read-only bits (git's pack files). A part-deleted `.gc-*` folder is swept by the next gc.
- **Doctor never changes anything.** It installs, fetches and writes nothing. Network checks have short timeouts. Exit 0 when no check fails, 1 when one does. `--json` gives every check.
- **The support bundle holds no secret and no personal data.** Every text file is first passed through the commons redactor (the environment's secret values, the gateway key, credential shapes). It is then passed through the publish scan in `mask` mode with no identity fields exempt. The finished archive is re-read and scanned once more: any hit fails the command and deletes the zip (fail closed). Config files are copied with secret-named keys dropped.
- **Limits are policy, not flags.** No CLI flag weakens them. A `None` limit is not applied.
- **Provider-agnostic.** No vendor names in core, policy fields or flags. Gateway model names come from policy.
- Never add `# fmt: skip` or `# fmt: off`. Line length 100. Check pytest exit codes directly. `uv run python scripts/check.py --all` must be green. TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.

   - a paused, awaiting-gate or running run of any age;
   - in org mode, a run with undelivered events;
   - a run whose tree has uncommitted work;
   - a run with a file held open on Windows.

   Tests: Task 2 `test_only_finished_old_runs_are_pruned`, `test_org_mode_keeps_undelivered_runs`, `test_dirty_tree_keeps_the_run`, `test_locked_run_folder_is_kept_on_windows`.
2. **The support bundle leaks nothing.** Secrets and PII are planted in the environment, the user config, step logs, run summaries and doctor details. None of them appears in any member of the zip, and the publish-scan verification pass fails closed. Test: Task 7 `test_planted_secrets_and_pii_never_reach_the_bundle`, `test_a_hit_after_redaction_fails_closed`.
3. **Resource limits really stop a runaway command on Linux** (memory, process count, CPU time), inside srt when it is installed and on the unsandboxed path. The limits cannot be raised by the command itself: hard limits are used. Tests: Task 8 `test_linux_*` (Linux stage), `test_command_cannot_raise_its_hard_limit`.
4. **Windows Job Object limits** stop a memory hog and a process spawner. The documented gaps are named in the runbook:
   - no file-size limit;
   - a child started before adoption escapes.

   Tests: Task 8 `test_windows_job_*`.
5. **D33 check.** Classic protection, rulesets, an unprotected branch and a token without admin rights each give the right verdict from recorded GitHub responses. With no token, doctor says "cannot check" and does not fail. Test: Task 5.

### Task 8: Sandbox resource limits, the mechanism (core)

**Files:**
- Create: `core/src/agentic/sandbox/limits.py`
- Modify: `core/src/agentic/sandbox/process.py`, `core/src/agentic/sandbox/srt.py`, `core/src/agentic/agents/tools/shell.py`, `core/src/agentic/backends/processes.py` (`_Job.containing(pid, limits)`)
- Test: `core/tests/sandbox/test_limits.py`

**Rulings (recorded in the runbook):**

| Limit | Linux | macOS | Windows |
|---|---|---|---|
| CPU | hard `RLIMIT_CPU` per process, through the launcher (SIGXCPU, then SIGKILL) | same | Job `PerJobUserTimeLimit`: the job's processes end when it is spent |
| Memory | watchdog: the tree's resident memory, polled every 0.1 s, kills the tree past the limit | same, through `ps` | Job `JobMemoryLimit`: committed memory; an allocation past it fails |
| File size | hard `RLIMIT_FSIZE` (SIGXFSZ / EFBIG) | same | not enforced (documented) |
| Processes | hard `RLIMIT_NPROC`, set to the user's current count plus the limit (the kernel backstop for non-root users), plus the watchdog's count of the tree (root, CI, macOS) | same | Job `ActiveProcessLimit` |

`RLIMIT_AS` is not used: V8 (Node) and the JVM reserve far more address space than they use, so `npm test` would fail.

- The launcher runs inside srt, around `bash -c`, so srt's own Node process is never limited.
- The launcher is `python -I`: a planted module in the tree cannot be imported.

**Interfaces:**
- `limits.launcher(limits, argv) -> list[str]` (POSIX; unchanged on Windows).
- `limits.Watchdog(limits, pid)`, with `.check() -> str | None`.
- `ShellResult.limited: str | None`: `"memory"`, `"processes"`, `"cpu"` or `"file size"`.
