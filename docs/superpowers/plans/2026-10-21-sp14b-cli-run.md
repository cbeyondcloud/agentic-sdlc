# SP14b CLI (run side) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A developer runs, watches, decides and costs pipeline runs from the `agentic` command: `run <pipeline>` (with `--dry-run`, which spends nothing and prints the resolved plan), `resume`, `status`, `runs`, `stop`, `logs`; the gate verbs `approve`, `reject --feedback`, `edit` (in `$VISUAL`/`$EDITOR`, Notepad on Windows) with the handoff and diff shown, and a `waiting` list of every gate across runs; `validate`, `agents|pipelines|skills list/search`, `agents new --type`, `pipelines new`, `policy show`; and `cost` with a run/step/agent/child breakdown that matches the ledger to the cent. Rows M1-54, M1-55, M1-56, M1-57.

**Architecture:**
- **`agentic_cli.workspace`** - where a command's inputs come from: the repository root (nearest `.git`), the repo config `.agentic/config.yaml` (classification), the org policy repo (`AGENTIC_POLICY_REPO`, else user config `policy_repo`, else `~/.agentic/policy/<org>/` from user config `org`, else the standalone `.agentic/local/policy/`), the team (`AGENTIC_TEAM` / user config `team`), and the user (`AGENTIC_USER` / user config `user` / the repo's `git config user.email`). It loads the policy and the three definition layers (org = policy repo, team = `teams/<team>/`, repo = `.agentic/`). One module so SP14a's `init` can write what it reads.
- **`agentic_cli.runtime`** - builds the engine for one workspace (DF-47): the run store (`.agentic/local/runs`), `recorder_for` (open or resume `RunLedger`, wrapped in `ForwardingRecorder` with no sinks in M1, DF-165), `gates_for` (`ZyrofloGates`), `block_on_for` (`regime_block_on`), `StepWiring` trees and tools, `StepRunners` with the native backend over the gateway (`GatewaySettings` from config + the credential provider), `StepLogs` with the commons redactor (the gateway key included, DF-165), and the local JSONL span exporter when the telemetry extra is installed. Preflight is run with the configured backends (DF-74 part), the installed skills (DF-136) and a CLI check that a `codeintel` tool has its adapter. Tests swap the network transport for a fake TokenLean (`httpx2.MockTransport`) and the sandbox readiness for a fixed one: no real provider is ever called.
- **`agentic_cli.wiring.StepWiring`** gains the step's installed skills and code intelligence (DF-87: a `CodeReviewGraph` over a `LocalIndex` of the run's tree, its data in run state) and a side-effect-free `unenforced_preview` for the dry run (DF-64; only the agent's own deny globs, DF-71's noise left out).
- **Command modules** (one `register(app)` each, one line in `COMMANDS`): `commands/runs.py` (run, resume, status, runs, stop, logs), `commands/gates.py` (approve, reject, edit, waiting, show), `commands/catalog.py` (validate, agents, pipelines, skills, policy), `commands/cost.py` (cost). Shared display helpers in `agentic_cli/display.py`; the editor launcher in `agentic_cli/editor.py`.
- **Exit codes from run state:** completed 0; paused at a gate or for a person 4; stopped, or paused at a limit (budget, run time, step turns/time/stuck) 5; failed 1. Engine error families (DF-54) map to: `EngineError`/`GateRefused` 2 (refused, nothing changed), `RunStateError`/`LedgerError`/`DefinitionError`/`PolicyError` 3 or 1 as the message says, `ExpressionError` 3.
- **Core changes (small, backward compatible):**
  - `preflight(..., skills=...)`: an agent whose resolved skills are not catalogued or not installed as pinned is refused (DF-136); an agent that inlines all its skills (no `activate_skill`, or the catalog's `preload_for`) with more than `MAX_PRELOADED` usable skills is refused (DF-144), and the loader records `skills.truncated` for each skill it drops.
  - `Engine.start` refuses inputs the pipeline does not declare and requires every declared input (DF-54); the runner factory is called inside the step's try, so a failure to build the step's runner pauses the run (`step-error`) and closes the budget slice (DF-69); `resume(skip=True)` skips the step (or leaves the loop) a `condition` pause is about (DF-59).
  - `BudgetSlice.child_spend` - what each closed child slice spent (descendants included), kept in the snapshot; the engine stores it on the step record (`children_usd`) and in the `step_finished` event's `cost` (`{"usd", "children"}`), so `cost` can break a step down by child (M1-57).
  - A `NullHandler` on the `agentic` logger (DF-175); the CLI routes `agentic` records to stderr at WARNING through the redactor and stops propagation to the root logger, so no unredacted traceback and no global level change reaches a console handler.

**Tech Stack:** Python 3.12; Typer 0.27.3 + Rich 15 (already dependencies of agentic-cli). No new dependency.

**Spec:** §8.2 (preflight output), §8.3 (gates persist and exit; approve/reject/edit; resume), §8.4 (limits pause for a human), §5.5/§5.7 (agent types and templates), §12.6 (catalog listing), §24 steps 5-8 (daily loop: pipelines list, run --dry-run, status, approve), §26 (cost). Master plan rows M1-54..M1-57.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Command parsing, help, exit codes | Typer 0.27.3 (MIT) via the M1-49 skeleton | - |
| Tables, Markdown handoffs, coloured diffs | Rich 15 (MIT): `Table`, `Markdown`, `Syntax(..., "diff")` | `difflib` rendering: git already computes the step's diff |
| Opening the editor | own 30-line launcher with Click's lookup order (`VISUAL`, `EDITOR`, then `notepad` on Windows, else `vi`) | `click.edit`: Click is not a declared dependency (Typer vendors a private copy, `typer._click`); importing a private module would break on a Typer upgrade |
| Diffs | `git diff <base> <commit>` in each component tree through `sdlc_commons.worktrees.worktree_git` (Zyroflo's git helper, D34) | GitPython / dulwich: an extra dependency for one command |
| Run ledger, approvals, redaction | Zyroflo through `sdlc_commons` (`RunLedger`, `ZyrofloGates`, `redactor`) | - |
| Cost figures | the run ledger's `step_finished` events (Zyroflo T446b `cost` field) and `run.json` | a separate cost store: two records could disagree |

## Global Constraints

- core never imports `sdlc_commons`, `agentic_cli` or Zyroflo; the CLI may import both (import-linter).
- Provider-agnostic: no vendor names in CLI flags, output labels or code paths; test models are called `acme/...`.
- Tests never call a real provider: the native backend runs over `httpx2.MockTransport` (a fake TokenLean OpenAI-compatible route with `x-tokenlean-cost-usd`) or scripted runners.
- Windows and macOS: paths via `pathlib`; files written with LF; the editor command split with `shlex.split(posix=os.name != "nt")`; no shell=True.
- `--json` everywhere through `Output.result`.
- Dry run writes nothing in the repository (no run folder, no worktree) and opens no network connection.
- never add `# fmt: skip` / `# fmt: off`; line length 100; check pytest's exit code directly.
- TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.
