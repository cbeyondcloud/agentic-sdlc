# SP10 Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agents get approved, hash-pinned Agent Skills (`SKILL.md`, agentskills.io). A catalog lists every approved skill with its source, licence and sha256. An installer copies the skills a repo needs into `.agentic/local/skills/`, read-only, and restores any local edit (logged as `skills.tamper_restored`). A loader puts a short catalog (or, for weak/local models, the full skills) into the agent's context, and `activate_skill` loads a skill on demand. Admission checks refuse unlicensed, malformed, oversized or script-carrying skills. A representative set of the default skills is vendored with a NOTICE.

**Architecture:**
- **New package `agentic.skills`** (core; imports neither `sdlc_commons` nor Zyroflo):
  - `catalog.py`: the `catalog.yaml` model (`Catalog`, `SkillEntry`), `load_catalog`, and `skill_digest(folder)` (the content hash).
  - `select.py`: which skills a repo gets: the union of the resolved `skills` of every agent in the enabled pipelines, plus opt-in packs, plus authoring skills only for admin roles.
  - `install.py`: `sync_skills`: install, verify, restore and prune in one idempotent call, run by `init` and before every run.
  - `loader.py`: `InstalledSkills` (the real `SkillCatalog` for `activate_skill`), `skill_prompt` (catalog block, at most 100 tokens per skill, or pre-loaded skill text), `estimate_tokens`.
  - `admission.py`: `admit(folder, key, catalog)` runs the checks `licence`, `validate` (`skills-ref`), `size` and `scan` (scripts, pipe-to-shell, hidden Unicode, prompt-injection phrases, telemetry URLs); `admit_catalog(root)` admits a whole catalog folder.
- **Agent tools.** `activate_skill` keeps its `SkillCatalog.get(name)` contract. It gains an optional `file` argument for a skill's bundled reference files (only when the catalog offers `resource`), and it refuses a tampered skill instead of crashing.
- **Step wiring.** `StepRunners` wraps a step's runner so the agent's instructions end with the skill block, when the step's tool context carries a skill library. No engine change.
- **Shipped content.** `library/skills/`: `catalog.yaml`, `THIRD_PARTY_NOTICES.md`, and one folder per skill, `<source>/<name>/` (with that source's licence text as `LICENSE.txt`).

**Tech Stack:** Python 3.12, `skills-ref==0.1.1` (Apache-2.0; deps click BSD-3, strictyaml MIT; pure Python; released 2026-01-10) as the optional extra `skills` of agentic-core, installed in the dev group. pytest.

**Spec:** `docs/superpowers/specs/2026-10-16-agentic-sdlc-design.md` §11 (mechanism, defaults, governance, exclusions), §4.1/§4.3 (where the catalog lives), §24 (personal vs shared skills, read-only shared skills). Master plan: the "Skills `init` downloads" table and rows M1-37..M1-40.

## Global Constraints

- **Catalog keys** are `<source>/<name>` (as agent files already name skills, e.g. `superpowers/test-driven-development`). The folder is `<root>/<source>/<name>/` and the `SKILL.md` `name` equals `<name>`.
- **Digest.** It is `sha256:` over every file in the skill folder, sorted by POSIX relative path: the path, NUL, the bytes with CRLF turned into LF, NUL. A Windows checkout and a Linux checkout get the same digest (master Review Focus 1, DF-02 lesson).
- **Shared skills are read-only.** Installed files are made read-only. `sync_skills` restores any difference: an edited file, an added file or a deleted file. Each restore is reported through the `record` callback as `skills.tamper_restored`, with the skill, the expected digest and the found digest.
- **Only catalog skills.** A wanted skill missing from the catalog is never installed. It is reported in `Selection.missing`. A catalog source folder whose digest differs from the catalog is refused with `SkillsError`, never installed.
- **Selection.**
  - Authoring skills (`audience: admins`) go only to users holding `org-admin` or `team-lead`, even when an agent lists one.
  - Pack skills go only when the pack is enabled (team policy `skill_packs`).
  - Excluded names (spec §11.4) are refused by the catalog model itself.
- **Loader.**
  - Each catalog line is at most 100 estimated tokens. The estimate is `ceil(utf-8 bytes / 3)`, a conservative bound for English text with no tokenizer dependency (provider-agnostic). A long description is cut at a word boundary.
  - At most `MAX_PRELOADED = 5` skills are pre-loaded (spec §11.3: 3-5 per role).
  - An agent is "weak/local" when its resolved tier or model matches the catalog's `preload_for` rule (tier names, model globs). The rule is empty by default, and no vendor or model names appear in code.
- **Provider-agnostic.** No vendor names in `agentic.skills`. The telemetry patterns are generic URL shapes plus a short list of analytics hosts in data.
- **Formatting, CI and records:**
  - never add `# fmt: skip` or `# fmt: off`; line length 100;
  - check pytest's exit code directly;
  - `uv run python scripts/check.py --all` must be green on Windows and Linux;
  - TRACKER.md and DEFERRED.md are updated by the coordinator from this track's output (parallel tracks).

## Review Focus

1. **A locally edited, added-to or partly deleted shared skill.** The next `sync_skills` restores it byte for byte and logs `skills.tamper_restored`. A read-only file does not make the restore fail on Windows. Test: Task 3 `test_an_edited_skill_is_restored_and_logged`, `test_an_added_or_deleted_file_is_restored`.
2. **A developer never receives authoring skills**, even if an agent definition lists one. An opt-in pack is absent unless the team enables it. Test: Task 2 `test_developer_never_receives_authoring_skills`, `test_opt_in_pack_absent_unless_enabled`.
3. **`activate_skill` with a name outside the agent's allow-list, or a `file` that escapes the skill folder** (`../../.ssh/id_rsa`, an absolute path). Both are refused and nothing is read. Test: Task 4 `test_activation_outside_allow_list_refused`, `test_skill_file_cannot_escape`.
4. **The same skill hashed on Windows (CRLF checkout) and Linux** gives the same digest. Test: Task 1 `test_digest_ignores_line_endings`.
5. **Each admission check rejects its bad fixture.** The cases are: a GPL skill; a malformed `SKILL.md` (name not matching its folder); an oversized skill; a skill with an unreviewed script; a skill with a pipe-to-shell line; a skill with hidden bidi characters; a skill with a telemetry URL. The vendored library passes every check. Test: Task 5, Task 6.

**Interfaces:**
- `class SkillsError(Exception)`.

  - `pack: str | None`;
  - `scripts_reviewed_by: str | None`;
  - `notes: str = ""`.

- `AdmissionLimits(max_skill_tokens=8000, max_total_bytes=262144, max_catalog_tokens=100)`.
- `Catalog`:
  - `skills: dict[str, SkillEntry]`, `excluded: dict[str, str]`, `licences: list[str]` (default MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, internal), `preload_for: PreloadRule`, `limits: AdmissionLimits`;
  - validators: keys match `^[a-z0-9]+(-[a-z0-9]+)*/[a-z0-9]+(-[a-z0-9]+)*$`; no key, or bare name, is in `excluded`.
- `load_catalog(root: Path) -> Catalog` reads `<root>/catalog.yaml` through `agentic.yamlio`.
- `skill_folder(root, key) -> Path`.

### Task 5: Admission checks (M1-39)

**Files:**
- Modify: `core/pyproject.toml` (`skills = ["skills-ref==0.1.1"]`), root `pyproject.toml` (the dev group gains `skills`); `uv lock`.
- Create: `core/src/agentic/skills/admission.py`
- Test: `core/tests/skills/test_admission.py`

**Interfaces:**
- `@dataclass(frozen=True) Rejection(check: str, path: str, reason: str)`.
- `admit(folder, key, catalog) -> list[Rejection]`. The checks:
  - `licence`: the entry's licence is allowed, a `LICENSE*` file exists unless the licence is `internal`, and an SPDX-like front-matter `license` agrees;
  - `validate`: skills-ref's errors. A missing extra is itself a rejection;
  - `size`: `SKILL.md` within `max_skill_tokens`, the folder within `max_total_bytes`;
  - `scan`:
    - script or binary files without `scripts_reviewed_by`;
    - pipe-to-shell and download-and-run lines;
    - hidden bidi or zero-width characters;
    - prompt-injection phrases;
    - telemetry or analytics URLs.
- `admit_catalog(root) -> dict[str, list[Rejection]]`: adds a `pin` rejection for a missing folder or a digest mismatch.
- `telemetry_urls(text) -> list[str]`.
