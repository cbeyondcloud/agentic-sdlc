# M3-04 environments (dev, staging, prod) - implementation plan

**Goal:** the umbrella chart `deploy/helm/agentic-platform` (M3-02) installs as three
environments from one chart: a values file per environment, optional External Secrets and
cert-manager TLS, the policy repo branch each environment tracks (`dev`, `staging`,
`main`), and promotion runbooks. Staging is a local kind cluster (owner decision 114):
done when the staging values install on kind and the promotion dry run is documented.

**Reuse:** External Secrets Operator (Apache-2.0) and cert-manager (Apache-2.0) are
consumed through their CRDs only (`ExternalSecret`, `Certificate`); nothing is vendored.
The kind smoke of M3-02 (`deploy/helm/kind/`) is extended, not copied.

## Interfaces

- Chart: `environment.name` (`""`, `dev`, `staging`, `prod`), `environment.policyBranch`
  (default from the name: dev -> `dev`, staging -> `staging`, prod -> `main`), rendered as
  `AGENTIC_CP_POLICY_BRANCH`.
- Setting `AGENTIC_CP_POLICY_BRANCH` (optional). When set it is the default branch of
  `admin tenant create` and `admin tenant set-policy-repo` and of `PUT /v1/tenant/policy-source`
  when the body omits `branch`; any other branch is refused (CLI exit 3, API 422
  `policy.branch_pinned`). Unset: today's behaviour (`main`).
- `environment.name=prod` refuses to render without ingress TLS (`ingress.tlsSecretName`) and
  without `externalSecrets.enabled` or `secrets.externallyManaged=true`.

## TDD steps

1. Settings + CLI + API tests for `policy_branch` (fail), then the setting and its use.
2. Chart tests: each environment renders; prod refuses missing TLS / unmanaged secrets; the
   policy branch differs per environment; ExternalSecret and Certificate shapes (fail), then
   the values files and templates.
3. DF-807 test (the Job has no metrics, SMTP or gateway secret), then the env mode.
4. DF-808 test (a 53-character release name gives unique names of 63 characters or fewer),
   then the name change.
5. DF-806 tests (exit 2 on a driver error, a quoted owner role, the created owner role is
   dropped), then the drill fixes.
6. kind: `ENVIRONMENT=staging` smoke on a cluster named `b16-m3-envs`; record the result in
   the runbook.

## Review Focus

- No secret value is ever rendered; the ExternalSecret only names remote keys.
- The ExternalSecret is a pre-install hook so the migration Job finds its Secret; the
  Secret is orphaned on purpose so re-creating the hook never deletes it.
- The branch pin cannot be bypassed by the API, the CLI or tenant creation.
- Old installs (no `environment`) render exactly as before apart from DF-807 and DF-808.
