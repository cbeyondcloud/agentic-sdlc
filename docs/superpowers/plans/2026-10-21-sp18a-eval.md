# SP18a Agent Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The framework can measure its agents. `agentic eval run --agent <x>` runs an agent over an eval corpus (k repeats per case), scores every run with objective metrics where they exist (schema validity, seeded-defect recall, seeded failing criteria caught, cost) and a blinded rubric judge from a different model family where they do not (BA, Design), and writes a JSON + Markdown report with per-case aggregates and confidence intervals. A pre-registered, hashed A/B plan decides PROMOTE / NO_BENEFIT / UNMEASURABLE with a paired sign-flip test. `agentic eval calibrate` exports a blinded sample for humans and scores the judge against them (weighted kappa). In CI the whole path runs on a small fixture corpus with recorded responses, served by a cassette server, with no model call. M1-59 adds 15 golden handoffs and a synthetic seed corpus in the case formats.

**Rows:** M1-63 (eval harness), M1-59 (quality assets). Method: spike S10 (`docs/spikes/S10-ab-eval-method.md`), decisions 17-20.

**Architecture:**
- **New package `agentic.eval`** (core; imports neither `sdlc_commons` nor Zyroflo; `pydantic_evals` only here):
  - `stats.py`: stdlib paired statistics: `per_case`, `paired_diffs`, `signflip_test` (decides), `paired_bootstrap` (reported), `sign_test`, `wilcoxon_signed_rank`, `wilson`, `cluster_bootstrap_ratio`, `weighted_kappa`, `benjamini_hochberg`, `pearson`.
  - `cases.py`: `EvalCase`, `CaseSource`, `CaseInputs`, `SeededDefect`, `TestTruth`, `Expected` (strict Pydantic).
  - `corpus.py`: `load_corpus(root, public=...)`, `build_manifest` / `write_manifest` (LF-normalised sha256 per file), `Corpus.select`, `Corpus.counts`, `floor_shortfalls` against decision 18.
  - `blind.py`: `Scrubber` (variant-distinguishing names, "Using skill"/"As the ... agent" tells, model self-identification), `assign_labels` (X/Y, seeded flip), `SealedMapping`, `LeakCheck`.
  - `judge.py`: `Rubric` (5 criteria x 0-2 anchors, versioned, sha256), `RubricJudge` (pointwise, verbatim evidence quotes, one re-ask, reference-guided, temperature 0), `PairwiseJudge` (both orders, order-dependent = tie), `resolve_judge` (tier `eval-judge`, family rule, `judge_same_family`).
  - `metrics.py`: pure metric functions (`schema_valid`, `match_findings`, `defect_recall`, `unmatched_blocking`, `qa_catch`) and the pydantic-evals `Evaluator`s that apply them and the rubric judge.
  - `runner.py`: `RunRequest`, `RunRecord`, `run_eval` (cases x labels x repeats, interleaved per case in seeded random order, budget cap, pydantic-evals `Dataset` as the engine), `AgentCaseRunner` (one case on `PydanticAIRunner` with the handoff contract).
  - `abtest.py`: `ABPlan` (pre-registered, sha256, `register_plan` records `eval.plan_registered` before any run), `decide` (verdict rule, guards), `run_ab`.
  - `report.py`: `EvalRun`, `MetricAggregate`, `EvalReport`, `build_report`, `render_markdown`, `write_report`, `comparable`.
  - `replay.py`: `CassetteServer`: stdlib HTTP, speaks `/v1/chat/completions`, `/v1/messages`, `/v1/responses`; replay and record modes; keyed by URL prefix `/c/<case>/<label>/<repeat>/...`.
- **Policy:** `TierSpec.family` (optional override of the vendor-prefix family rule); an `eval.yaml` file with `EvalPolicy` (`max_cost_increase`, `repeats`, `budget_usd` per agent). No vendor names in code: the judge is whatever admins map to tier `eval-judge`.
- **Agents:** `agentic.agents.models.build_model_for(model_id, ...)`, the model-id half of `build_model` (which now delegates to it), so the judge gets a TokenLean-routed model without a resolved agent.
- **CLI:** `cli/src/agentic_cli/commands/eval.py`: `agentic eval run` and `agentic eval calibrate export|score`; the ledger events go to a `RunLedger` (commons) opened for the report.
- **Shipped content (M1-59):** `library/eval/golden/<kind>/` (3 golden handoffs per kind), `library/eval/rubrics/`, `library/eval/corpus/` (synthetic seed corpus, manifest), `library/eval/fixtures/` (CI fixture corpus: policy, fixture agents, cases, cassettes, expected reports).

**Tech Stack:** Python 3.12; `pydantic-evals==2.54.0` (MIT, released 2026-10-03, same release as our `pydantic-ai-slim`; its other deps already locked) as the optional extra `eval` of agentic-core, required by agentic-cli and the dev group. pytest. scipy is used only to generate committed test vectors inside the Linux container; it is not a dependency (see OSS decisions).

**Spec:** `docs/superpowers/specs/2026-10-16-agentic-sdlc-design.md` §11 (skill A/B before promotion), §20-21 (agent-quality evals, corpus replay, pre-registered judging), §24. Spike S10 is the method of record.

## Global Constraints

- **Provider-agnostic.** No vendor names, model names or vendor flags in `agentic.eval`, the CLI or the policy model. The judge is the model behind tier `eval-judge`; its family is the prefix of its model id before `/`, or the tier's `family:`.
- **Always an explicit judge model.** Nothing calls pydantic-evals `LLMJudge`; every judge `Agent` gets its `Model` object. `agentic.eval` sets `PYDANTIC_AI_NO_BANNER=1` (setdefault) before importing pydantic-ai or pydantic-evals.
- **No real model calls in tests.** Tests use `FunctionModel`/`TestModel` or the cassette server.
- **The case is the unit.** Repeats are averaged within a case before any statistic; every CI resamples cases; unscored cases are named beside the denominator.
- **None is unmeasurable, never 0.** A metric that cannot be computed is absent from the run's metrics and counted as unmeasurable in the aggregate.
- **Blinding.** Judges see only scrubbed text. Every judge input passes the `LeakCheck`; any hit makes the report `UNMEASURABLE` (the run is void, not a pass).
- **Determinism.** Every random choice (label flip, run order, bootstrap, sign-flip) takes a seed recorded in the report. Files are written with LF; hashes are over LF-normalised bytes, so Windows and Linux agree.
- **Cassettes.** A missing cassette or a call-count mismatch fails the run; a request-hash mismatch counts as `stale_cassettes` (a warning). Secrets (`authorization`, `x-api-key`) are never written to a cassette.
- **Corpus licensing (decision 17).** `library/eval/` holds only `synthetic: true` cases or cases whose `source.licence` is on the permissive allow-list; `load_corpus(public=True)` enforces it.
- **Formatting, CI and records:** never add `# fmt: skip` or `# fmt: off`; line length 100; check pytest's exit code directly; `uv run python scripts/check.py --all` green on Windows and Linux; TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.

## Review Focus

1. **A blinding leak voids the run.** A variant-distinguishing name the scrubber was not told about reaches a judge input: the report verdict is `UNMEASURABLE` with the leaked term named. Test: Task 3 `test_leak_check_finds_unscrubbed_terms`, Task 7 `test_a_leak_makes_the_ab_unmeasurable`.
2. **Statistics match scipy.** Sign test, exact and normal-approximation Wilcoxon, Wilson, weighted kappa and BH agree with the committed scipy vectors to 1e-12. Test: Task 1 `test_matches_scipy_vectors`.
3. **The judge is never defaulted and never the candidate's family when policy offers another.** Test: Task 4 `test_judge_from_a_different_family`, `test_same_family_is_flagged`, `test_missing_judge_tier_refused`.
4. **Cassette mismatches.** A missing cassette and an extra or missing call fail the run; a changed prompt is `stale_cassettes: 1` and still replays. Test: Task 8.
5. **The A/B plan is registered before the first run** and its sha256 is in the report; changing any field changes the sha. Test: Task 7 `test_plan_registered_before_any_run`.
6. **Fixture mode end to end** (`agentic eval run` on `library/eval/fixtures`) reproduces the committed expected reports on Windows and Linux. Test: Task 10 `test_fixture_corpus_matches_expected_reports`.

### As built (differences from the tasks above)

- **scipy vectors** are generated in the Linux container and committed; scipy is not in the lock (numpy's licence includes Zlib, and native wheels would run on Windows hosts).
- **Ledger events.** Zyroflo's ledger accepts only its lifecycle events, so `EvalLedger` (CLI) maps `eval.run_started` / `eval.plan_registered` / `eval.ab_decided` / `eval.report_written` onto `step_started` / `step_finished` (artifacts carry the plan or report sha) and `run_closed`.
- **Calibrate** has two subcommands, `export` and `score` (`score` reads the raters' files; there is no separate `import`).
- **Judge view.** The judge (and the raters) see the handoff without its framework envelope; a score of 0 needs no evidence quote.
- **Matching** of review findings is a maximum one-to-one matching (Kuhn), not greedy.
- **Budget.** 30 % of the eval budget is held for the judge; an agent hitting its own per-run limit is a scored failure, the eval cap makes runs unscored and the report INCOMPLETE.
- **Not built (deferred):** `agentic eval ab` / `eval gate` / `eval harvest` commands, running dev tasks in a sandboxed worktree (so `tests_pass` stays unscored), false-finding adjudication, the decision-18 corpus counts.
