# Day-0 Bootstrap Implementation Plan (M3-05, track b17-m3-05)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One ordered path a platform team follows from nothing to a working org: the policy repo from `templates/policy-repo/`, git credentials (GitHub App or token) and the Jira connector, SMTP, the first org admin and roles, the CLI on the internal index, and a smoke run. A runbook (`docs/runbooks/day-0-bootstrap.md`) and one script (`scripts/bootstrap.py`) that reuses the existing commands (`python -m agentic_cp admin ...`, `agentic rbac ...`, `agentic login`, `scripts/release.py`, the kind smoke) and adds only what is missing. Done when a fresh staging on kind is bootstrapped end to end from the runbook alone. Also closes the DF items targeting M3-05 where they fit, and DF-857.

**Architecture:**
- **`scripts/bootstrap.py`** (standard library only; `uv run python scripts/bootstrap.py <step>`). One file for Windows, macOS and Linux, like `scripts/release.py` and `scripts/restore_drill.py`; paired `.sh`/`.ps1` stay where a pinned tool container must be started (the kind smoke). Each step checks before it changes anything, can be run again, and never prints a secret:
  - `policy-repo`: a new git repo from the template plus the framework library, with the org's handles, repo patterns, models and CLI version filled in; branches `main`, `staging`, `dev`; the policy-repo gate (`agentic policy check`) must pass.
  - `git-credentials`: the per-tenant `<slug>.gitconfig` (a credential helper reading a token file from the same mounted Secret, and optionally a CA file) for the chart's `gitConfigSecret`.
  - `tenant`: through the chart's operator pod (`kubectl exec`): `admin tenant create` (the first org admin; the token goes to an owner-only file, never the terminal), `admin tenant set-policy-repo`, and the operator scaled back to zero.
  - `people`: `agentic rbac assign` per person (the existing CLI, with the admin token in `AGENTIC_CONTROL_PLANE_TOKEN`); prints whether each invite was mailed (DF-575).
  - `verify`: the checklist over HTTP: `/readyz`, `/v1/me`, `/v1/policy/active`, assignments, invite mail status, the CLI's packages on the index; exit 1 on any failure; manual items are listed as MANUAL.
  - `smoke`: a developer's first session: `agentic login --invite <link>` (or a token), org mode, `agentic init`, `agentic run feature-delivery --dry-run` with the org checks; no model is called.
- **Chart:** `operator` Deployment (DF-892), zero replicas by default, same image, env, Secret keys, git config and policy branch as the API, plus the owner DSN; restricted security context.
- **Control plane:** `db backup-role` (DF-891); mail robustness (DF-578); settings warnings and invite notes (DF-575).
- **Policy-repo template:** the policy-check install line names published packages (DF-598); a budget guard (DF-857) run from the base branch on every pull request and review.
- **Local proof:** `deploy/helm/kind/bootstrap_proof.py` drives the runbook on kind (cluster `b17-m3-05`): containers `b17-m3-05-mailpit` (fake SMTP) and `b17-m3-05-git` (local smart-HTTPS git) on the kind network, staging values plus a bootstrap values file, then every `bootstrap.py` step, then `verify` and `smoke`.

**Tech Stack:** Python 3.12 standard library (bootstrap), Helm, existing control-plane and CLI code. Mailpit (MIT) as the local SMTP. `codeowners` 0.9.0 (MIT, already locked) in the budget guard.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Fake SMTP with an API | Mailpit (`axllent/mailpit`, MIT) | MailHog (MIT) is unmaintained since 2020; smtp4dev is BSD-3 but heavier (.NET) |
| Local git over HTTPS | `git http-backend` (in the control-plane image) behind a 60-line stdlib server | Gitea (MIT): a full forge to start for one repo; dumb HTTP cannot serve the control plane's `fetch --depth` |
| CODEOWNERS matching | `codeowners` 0.9.0 (MIT), already the control plane's | writing a matcher; the CLI may not import it (server-libraries contract), so the guard is a CI script |
| GitHub App tokens in the cluster | External Secrets Operator's `GithubAccessToken` generator (Apache-2.0), documented | our own token minting: a JWT signer and refresher to maintain |
| Package index locally | `scripts/tests/local_index.py` + `scripts/release.py publish` | pypiserver (zlib/libpng + MIT, not on the allow-list as a whole) |

## Review Focus

1. No secret on a terminal, in a log, in a process listing or in a committed file: the first admin's token, DSNs, the SMTP and backup passwords.
2. The budget guard cannot be bypassed by the pull request it checks (the guard and CODEOWNERS come from the base branch), and fails closed when it cannot tell who is an org admin.
3. The operator Deployment holds the owner DSN: zero replicas by default, no service account token, restricted pod security.
4. Bootstrap steps are idempotent and say what to do next when a check fails.
5. Windows and macOS both: `uv run` only, no shell features in `bootstrap.py`.
