> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No Open DEFERRED.md item that targets an M1 row and whose code is in `cli/`, `templates/`, `library/agents|pipelines|skills` (or their tests) is left open, except those that need live models, a Mac or the owner (M1-64, the live half of M1-68, M1-72, DF-61/DF-251). Each item is re-graded by what it does to a developer on a Windows or macOS laptop in a 1000-person org: **Fix** it (test first) when it can cause wrong behaviour, a security or safety gap, data loss, a confusing failure or a cross-platform break; **Accept** it with a one-line reason when it is cosmetic or theoretical; **Retarget** it to the M2/M3 row that owns it. First-run UX on Windows and macOS gets most of the attention.

**Architecture (no new module, no new dependency):**
- **`agentic_cli.repo_guard`** (M1-50): git runs with `core.quotePath=false`, so non-ASCII folder names are read as they are (DF-195). `normalise_remote` lower-cases first and never reads `:digits/` as a port in the scp form (DF-199). Check 3 refuses a linked worktree nested inside its own main tree (DF-200). Check 5's empty allow-list names the org admin (DF-211). Check 6 names the default branch when the config is committed there but not on HEAD (DF-198). Check 7 says what to do when the default branch cannot be found (DF-197).
- **`agentic_cli.repo_setup`** (M1-52): the create-only `update-ref` uses git's empty old value (works for SHA-1 and SHA-256 repos); `commit-tree` signs (`-S`) when `commit.gpgSign` is on, because plumbing ignores that setting (DF-210). The AGENTS.md scan reads `ls-tree -z` (DF-195).
- **`agentic_cli.policy_source`** (M1-53): the org policy cache is swapped by rename (old aside, new in, old removed), the scratch folder is removed, and a bad `policy_cache_hours` is exit 3 (DF-201).
- **`agentic_cli.dev_init` / `readiness`** (M1-51, M1-53): skills discovery honours `allow_repo_pipelines` in every mode and retries without the repo layer when a repo pipeline file is broken (DF-204); `init.tool_fetched` records the org manifest's `signed` attestation (DF-208); the Git Bash check prefers Git for Windows' bash and warns when only the WSL launcher is on PATH (DF-209).
- **`agentic_cli.runtime` / `wiring`** (M1-54): preflight refuses a tier whose model is still the `change-me` placeholder (DF-225). Without the codeintel extra (or with `codeintel.adapter: none`), agents run without the codeintel tools and preflight warns, instead of refusing every library pipeline: a null adapter that supports no operation yields no tools (DF-226). Skills restored before a run (a local edit) become preflight warnings (DF-186).
- **`agentic_cli.main` / `output` / `exit_codes`** (M1-49): `NO_COLOR` is honoured; a non-usage Click error is a clean exit 1; usage errors are JSON under `--json`; an unreadable user config is exit 3 (DF-252). The exit-code table says that exit 1 also means "init not ready" and "CI not green" (DF-196, DF-298; a dedicated code stays an owner decision).
- **Run and gate UX** (M1-54, M1-55): next steps at an exhausted loop gate put edit and reject first (DF-321/DF-266); a refused edit the engine already recorded no longer points at a stale draft (DF-348); `runs` piped or redirected uses the full table (DF-351); `--json run` prints `{"started": id}` on stderr when the run starts (DF-352); an end-to-end cp1252 test covers result JSON on stdout (DF-354).
- **Publishing** (M1-58 follow-ups): the PR title goes through the redactor (DF-295); the generated body sits between `<!-- agentic:run -->` markers and a re-publish replaces only that region, keeping a person's edits (DF-296; `PullRequest.body` is added in core, defaulting to None); the cost never prints in scientific notation (DF-318); SSH-alias and renamed-repository failures get hints (DF-299).
- **Eval CLI** (M1-63): the eval ledger run is closed even when the report step fails (DF-260); `--policy`/`--agents` messages read properly and a missing folder is a usage error (DF-259); a judge and agent sharing a gateway prefix with no `family:` get a warning (DF-302); `failure()` names the real cause and maps a budget stop to exit 5 (DF-254).
- **Library agents** (M1-60): QA and QA-baseline count collection and setup errors as failed tests; a red-baseline dry run passes end to end (DF-231). The rubric drift test also checks the deductions and the 8.0 critical cap (DF-235; `sdlc_commons.lifecycle.review_deductions`).
- **Acceptance suite** (M1-81): stale cassettes warn, and fail with `AGENTIC_ACCEPTANCE_STRICT=1` (DF-316).
- **Docs:** spec §4.2/§4.3 list the files init really proposes and the policy files the loader reads (DF-207); the SP18a plan's judge wording (DF-262) and the M1-81 CLI plan's diff cap (DF-355) are corrected.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Atomic folder swap | stdlib `os.replace` plus the existing `_replace_retrying` (antivirus-held handles on Windows) | `atomicwrites` (archived, files only) |
| Non-ASCII git paths | git's own `core.quotePath=false` and `-z` output | a home-made C-quote decoder |
| Signed init commit | `git commit-tree -S` (git uses the person's own gpg/ssh signing setup) | a signing library |
| PR body region update | HTML comment markers (what GitHub's own templates and bots use) | a Markdown parser |
| Colour control | Rich's own `NO_COLOR` handling (pass `no_color=None`) | — |

## Global Constraints

- Windows and macOS first: non-ASCII paths, PowerShell 5.1/7 and zsh, antivirus-held folders, 80-column terminals, pipes.
- Exit codes keep their meaning; `--json` stdout stays one document (the run-start line goes to stderr).
- No vendor names in CLI flags, messages or core types. Never add `# fmt: skip` or `# fmt: off`; line length 100; check pytest's exit code directly.
- TRACKER.md, DEFERRED.md and DECISIONS are left to the coordinator.
- `uv run python scripts/check.py --all` must be green.
