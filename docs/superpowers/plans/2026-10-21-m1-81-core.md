# M1-81 Hardening (core runtime) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close or record every Open DEFERRED.md item that targets M1-81 and comes from the core runtime sub-plans (SP1, SP3, SP4, SP5, SP6, SP6 on-fail, SP7, SP19). Each item is re-graded by what it does to a Windows or macOS developer in a 1000-person org: fixed with a regression test when it can cause wrong behaviour, a safety gap, data loss, a confusing failure or a cross-platform break; accepted with a one-line reason when it is cosmetic or theoretical; retargeted when another row owns it.

**Architecture:** No new modules and no new dependencies. Every fix is local to the file that has the defect, under `core/src/agentic/{definitions,policy,handoffs,engine,agents,backends}/` and `core/src/agentic/yamlio.py` (the YAML writer the handoff finaliser uses), plus the pipeline template comments and the call-flow diagram for the SP6 on-fail documentation item. The engine keeps its public interface; gate decisions change order (validate and check before writing an edit) but not their results for an accepted decision.

**Tech Stack:** Python 3.12, Pydantic 2, Pydantic AI 2.54, ruamel.yaml (all already locked). pytest.

**Spec:** `docs/superpowers/specs/2026-10-16-agentic-sdlc-design.md` §5.1 (agent files), §4.3 (policy files), §7 (handoffs, gates), §8.3-8.5 (engine, limits, loops), §9.1 (backends). Tracker row M1-81 and the DEFERRED.md items listed below.

## Global Constraints

- **Cross-platform.** Hashes and digests read text with LF line endings and no byte-order mark, so a Windows checkout and a Linux or macOS one agree. Agent names are lower case, so two names never collide on a case-insensitive file system (Windows, macOS).
- **Backward compatible.** Every shipped agent (`library/agents`, `library/eval/fixtures/agents`, `core/tests/fixtures`) already meets the name rules. The handoff catalog digest must not change (the blank check is a validator, not a schema change), so no paused run is refused after the upgrade.
- **Provider-agnostic.** No vendor names in `engine/`, `policy/`, `handoffs/`, `agents/` (except the routing module `agents/models.py`) or `backends/base.py`.
- **Formatting, CI and records:**
  - never add `# fmt: skip` or `# fmt: off`; line length 100;
  - check pytest's exit code directly;
  - `uv run python scripts/check.py --all` must be green on Windows and Linux;
  - TRACKER.md and DEFERRED.md are updated by the coordinator from this track's output.

## Review Focus

1. **A refused approval never leaves an edit behind.** At an exhausted loop gate, an edit that does not make `until` hold is refused and nothing is written; at any gate, an edit refused because another pinned file changed is not written either. Test: Task 5 `test_a_refused_edit_at_an_exhausted_gate_is_not_written`, `test_an_edit_is_not_written_when_another_pinned_file_changed`.
2. **The same policy folder hashed from a CRLF checkout and an LF one** gets one `sha256:` version. Test: Task 1 `test_policy_version_ignores_line_endings_and_bom`.
3. **A restored step re-runs with its whole budget:** child slices cut off by a crash are closed (their spend kept), not held. Test: Task 6 `test_a_restored_step_does_not_keep_holding_its_crashed_childrens_budget`.
4. **Runner outcomes say what happened:** an unrelated model failure after one refused answer is an error, not `invalid`; a turn limit after a refused answer carries its errors. Test: Task 4.
5. **No paused run is refused after the upgrade:** `BUILTIN_CATALOG.digest` and an extended catalog's digest are unchanged by Task 2. Test: Task 2 `test_blank_check_does_not_change_the_digest`.
