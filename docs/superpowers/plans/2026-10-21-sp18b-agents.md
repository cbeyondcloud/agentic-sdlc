# SP18b Built-in Agents, Pipelines and Standalone Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The framework ships working defaults. `library/agents/` holds the five built-in agents (Business Analyst, Design, Developer, Code Review, QA) plus a `qa-baseline` agent that records the test baseline at intake. Their instructions are adapted from Zyroflo's lifecycle SOPs (P0-P6, P10) and the Code Review agent scores with Zyroflo's review rubric (weights sum to 10). `library/pipelines/` holds `feature-delivery` and `bugfix`. Both pass preflight, have a clean compatibility check and run end to end through the engine with fake models. `templates/standalone/` is a policy a person can use without an org: provider-agnostic tiers mapped to placeholder models, limits, classifications, agent types, sandbox defaults, and a `preload_for` rule naming the local tier (decision 34). The remaining default skills (DF-134) are vendored, after the skill digest is made unambiguous and link-proof (DF-140).

**Architecture:**
- **Content, not code.** Agents and pipelines are definition files that the existing loaders (`load_agent`, `load_pipeline`, `DefinitionSet.discover(org=library)`) read unchanged. The standalone policy is a folder that `load_policy` reads unchanged.
- **One small schema change (baseline at intake).** `test-report` gains two optional fields: `failures` (names of the failing tests) and `baseline_failures` (tests that already failed at intake, copied from the baseline report). A `pass` verdict is allowed with failures only when every failure is named and was already failing at intake: Zyroflo P5's "no NEW failures" rule. A report without the new fields validates as before (D37: optional fields only).
- **Zyroflo is read, never copied into core.** The SOP and rubric text is adapted into the agent bodies (MIT, same owner). A commons test reads the live SOPs and rubric through `sdlc_commons.lifecycle`. It fails if the rubric categories or weights in the Code Review agent drift from Zyroflo's, or if a source stage disappears.
- **Skill digest v2 (DF-140).** `skill_digest` walks the folder without following links and refuses any symlink or junction (`SkillsError`). It hashes `len(path) path len(content) content` with 8-byte big-endian lengths, so two layouts can never collide. `_scan` reports junctions as links too. Every catalog pin is redone in one go.

**Tech Stack:** Python 3.12, existing deps only (pydantic-ai `TestModel` / `FunctionModel` for the smoke and dry-run tests). No new dependency.

**Spec:** §5.4 (built-in agents and their SOP sources), §5.5 (agent types), §6 and §6.2 (library pipelines), §7.2 (handoff kinds), §11.2 and §24 (default skills per role), §12.4 (classifications), §24 "Trying it without the org setup". Decision 34 (`preload_for` named in the standalone template). DEFERRED: DF-134, DF-140 (DF-141 is already Done).

## Global Constraints

- **Provider-agnostic.** No vendor, model or product names in the agent files, pipelines or the standalone template. Tier names are capability names (`deep-reasoning`, `balanced`, `fast`, `local`). Template models are `change-me/...` placeholders the user edits. A test greps the template and the agent files for vendor names.
- **Agent files validate against the standalone policy.** Every library agent resolves with no violation against `templates/standalone/policy`, and every skill its type names is in `library/skills/catalog.yaml`.
- **Compatibility clean.** Both pipelines produce zero compatibility findings, warnings included: no conditional producer of a consumed kind.
- **Baseline at intake.** Both pipelines run `qa-baseline` before any code changes. The QA agent judges against that baseline: no new failures.
- **Review exit rule.** The review loop ends on `review.open_blocking == 0`. The rubric score is reported and never gates (Zyroflo P6).
- **Skill pins.** Vendored skills are pinned at upstream commits on or before 2026-10-07, each with `LICENSE.txt`, a `THIRD_PARTY_NOTICES.md` row and a catalog hash. The digest change re-pins every skill in the same commit.
- **Formatting, CI and records:** never add `# fmt: skip` or `# fmt: off`; line length 100; check pytest exit codes directly; `uv run python scripts/check.py --all` green on Windows and Linux; TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.

**Interfaces:**
- `skill_digest(folder) -> str`: raises `SkillsError` naming the first link found. Hash per file, sorted by POSIX path: `u64be(len(p)) p u64be(len(c)) c` (CRLF counted as LF).
- `skill_files(folder) -> tuple[list[Path], list[Path]]`: (files, links), never following a link.
- `admit_catalog`: a digest `SkillsError` becomes a `pin` rejection, not a crash. `_scan` uses `skill_files`, so junctions are reported.
