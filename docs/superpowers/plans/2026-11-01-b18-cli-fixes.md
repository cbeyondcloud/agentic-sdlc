# b18-cli-fixes: GitHub adapter, sign-in and Jira leftovers

**Goal:** close the open code items on the GitHub adapter, sign-in and Jira so M1-58 can be
marked Done: DF-299 and DF-295 (already fixed in 4fd14b6; records only), DF-543, DF-547,
DF-548 (Jira), DF-952 (`login --invite` writes the user config), DF-955 (a credential
store that works in WSL2 without an OS keyring) and DF-954 (security reviewers in the
policy-repo template's CODEOWNERS).

**Architecture:** small, local changes. The Jira fixes stay in the existing client
(`core/src/agentic/integrations/jira.py`) and the CLI mapping (`cli/src/agentic_cli/jira.py`).
The user-config writer is a new function in `cli/src/agentic_cli/config.py` that edits the
file as text, guided by ruamel's line numbers, so nothing else in the file changes. The
credential fallback is a small file store in core (`agentic.auth.filestore`) that the
`Credentials` provider uses only when it is given one; the CLI decides whether to give it
(`agentic_cli.credential_store`), from the user config, `AGENTIC_CREDENTIAL_STORE` and the
cached org policy (`credential_file_fallback` in `policy/org.yaml`).

## Interfaces

- `JiraClient(...)` raises `JiraError` (never `UnicodeEncodeError`) for a token holding
  characters a header cannot carry; `_send` turns `httpx2.InvalidURL` and IDNA
  `UnicodeError` into a `JiraError` naming jira.url.
- `jira_failure(error, token)` gives transient errors a hint: Retry-After seconds when Jira
  sent them, otherwise "try again in a few minutes", and for an unreachable site the
  proxy (`HTTPS_PROXY`/`NO_PROXY`) and CA (`SSL_CERT_FILE`) settings.
- `request_text(item, key)` header: `Jira issue KEY: <summary>` (control and format
  characters and `<`/`>` removed, whitespace collapsed, cut to 80 characters).
- `set_user_config(home, values) -> ConfigChange` (written, changed keys with old values,
  or why it could not write); `agentic login --invite ... [--print-config]`.
- `FileStore(path)` with the keyring protocol; `Credentials(..., file_store=None,
  prefer_file=False)`; `Credentials.store` returns `"keyring"` or `"file"`;
  `Credential.source` may be `"file"`.
- `agentic_cli.credential_store.cli_credentials(env, home) -> Credentials`;
  `store_setting(...)`, `fallback_forbidden(...)`; doctor check `credential store`.
- OrgPolicy `credential_file_fallback: bool = True`.

  user chose it, and never when org policy or `AGENTIC_CREDENTIAL_STORE=keyring` forbids.

  is left alone and the lines are printed instead.
