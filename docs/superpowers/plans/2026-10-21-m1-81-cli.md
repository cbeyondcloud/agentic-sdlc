# M1-81 hardening, CLI area: first-run UX and safety fixes

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close or re-grade every open DEFERRED.md item that targets M1-81 and comes from the CLI sub-plans (SP14a, SP14b, SP17, M1 finishing). Each item is graded by what it does to a developer on a Windows or macOS laptop in a 1000-person org. Fix it (test first) when it can cause wrong behaviour, a safety gap, data loss, a confusing failure or a cross-platform break. Accept it with a reason when it is cosmetic or theoretical. Retarget it when an M2/M3 row owns it. Only `cli/`, `templates/` and their tests change. Two exceptions, both small: one test in `scripts/tests/` (DF-285 b) and the CLI package metadata.

**Architecture (no new module, no new dependency):**
- **`agentic_cli.output`**
  - The consoles render with Rich markup off by default. The few styled lines (`warning:`, `error:`, readiness marks, `Prepared branch`) turn it on and escape the user text inside them with `rich.markup.escape`. So a `[/x]` in a run id, pipeline name, path or engine reason can no longer raise `MarkupError`, and `[bold]x` is no longer swallowed. Table cells and rule titles are covered too (DF-218, DF-202 part).
  - The stream encodings the OS gave the process are recorded in `agentic_cli/__init__.py`, before any heavy import. Zyroflo's `tools` package reconfigures stdout/stderr to UTF-8 when it is imported. JSON (results and errors) is ASCII-escaped when the original stream was not UTF-8 (a Windows pipe or redirect), so `agentic --json ... | ConvertFrom-Json` in Windows PowerShell 5.1 gets non-ASCII user names and paths exactly. Human text stays UTF-8, as it ships today; the docstring says so (DF-283).
- **`agentic_cli.workspace` / `policy_source` / `config`:** there is one rule for where the policy comes from.
  - Org mode (`org:` set): `policy_repo` is the *source* init clones from (often an https URL), and later commands read the cache. Today `Workspace` treats an https `policy_repo` as a folder, so every org user's `agentic run` fails with "no org policy found (https:\...)".
  - Standalone: `policy:` and `policy_repo:` both name a local policy folder (init read one key, later commands the other).
  - `init --standalone --policy X` is remembered for this repo through `.agentic/local/init.json`, which init already writes (`policy_source`). Later commands use it when no environment or user setting overrides it. A recorded source inside the repository is ignored, so a repo cannot point the policy at its own files (DF-274).
- **`agentic_cli.policy_source.LoadedPolicy.commit`:** the standalone template is moved to a sibling `.standalone.tmp-<pid>` folder under `~/.agentic/policy/` first, then renamed into place. A failure part-way through never leaves a half-copied `standalone/` that later runs treat as installed (DF-281).
- **Commands**
  - `run`: `--run-id` is checked before anything else (exit 64). The run id is printed on stderr when the run starts, so after Ctrl-C the person knows what to resume (DF-219, DF-221).
  - `edit`: the gateway is checked before the editor opens. A UTF-8 BOM (Notepad) is accepted. Non-UTF-8 text is a clear exit-3 error that keeps the draft. A failed or refused decision keeps the draft, and the next `agentic edit` continues from it (the draft is keyed by the pinned file's digest, so a stale draft is never reused). A recorded decision removes it (DF-220).
  - `agents new`: the agent is validated before anything is written (DF-220).
  - `show`: `git diff` runs with `--no-ext-diff --no-textconv`, and a diff over 256 KiB is cut with a note (DF-222 e; the code and the ruling use 256 KiB, DF-355).
  - `run`, `validate` and `pipelines list/search` show `DefinitionSet.warnings` (ignored repo pipelines) (DF-222 f).
  - `runs`: on a terminal narrower than 100 columns the table drops the pipeline and updated columns, so it stays readable in an 80-column macOS Terminal (DF-222 b).
  - `logs --follow`: it exits with the run's exit code (0 completed, 1 failed, 4 waiting, 5 stopped) (DF-285 a).
- **`init`**
  - Developer mode, not set up yet, standalone: the hint is `agentic init --repo --standalone`.
  - When init is not ready, the message names the items to fix (for example `policy: models`) instead of reading like a machine failure.
  - `init --repo` in standalone mode, or with no origin, also offers `git merge agentic/init`. With no origin, init does not try to open a pull request (DF-284).
  - A tool installed with `--install-missing` that is not on PATH gets a fix line with the PowerShell and zsh commands to add its folder (DF-191 part).
  - The readiness item names no longer read `sandbox: sandbox`, and a standalone dry-run plan says `policy`, not `org` (DF-279, DF-286).
- **Packaging:** `cli/pyproject.toml` declares `httpx2`, which the CLI imports directly (DF-206).
- **Exit-code table:** exit 4 is described as "paused, waiting for a person (a gate, a tool approval, or a step error or policy pause to resume or stop); `--json` `pending` says which" (DF-221 part).

**Tech Stack:** Python 3.12, Rich (`rich.markup.escape`), stdlib `os.replace`/`hashlib`. No new dependency.

**Spec:** §8.1, §8.2, §8.3 and §24 (CLI, init, standalone). Tracker row M1-81 and its Notes. DEFERRED.md items listed below.

## Global Constraints

- Windows and macOS first: paths with spaces and non-ASCII characters, PowerShell 5.1/7 and zsh, CRLF from editors, 80-column terminals.
- Exit codes keep their meaning. `logs --follow` adopting the run's exit code is the only change, and it uses the existing codes.
- JSON keys do not change. Only how non-ASCII characters are escaped changes, which is invisible to a JSON parser.
- Never add `# fmt: skip` or `# fmt: off`. Line length is 100. Check pytest's exit code directly.
- `uv run python scripts/check.py --all` must be green. TRACKER.md, DEFERRED.md and DECISIONS are left to the coordinator.

## Review Focus

1. A run id, pipeline name, path or reason containing `[/x]` or `[bold]` is printed literally by `warn`, `error`, tables and `show`. Test: `test_output_markup.py`.
2. An org user (`org: acme`, `policy_repo: https://...`) runs commands from the cache. A repo-committed `init.json` cannot point the policy inside the repo. Test: `test_workspace.py` new cases.
3. A crash part-way through the standalone install leaves no `standalone/` folder. Test: `test_init_standalone.py::test_a_failed_install_leaves_no_partial_policy`.
4. `edit` never loses the person's text: missing gateway (checked first), invalid UTF-8, refused decision. Test: `test_gate_commands.py` new cases.
5. JSON through a cp1252 stream is ASCII-escaped and exact. Test: subprocess end-to-end in `test_output_streams.py`.
