# M3 Umbrella Helm chart, Postgres restore drill and upgrade runbook (M3-02)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The platform team installs the framework's server side on any Kubernetes cluster from one umbrella chart, `deploy/helm/agentic-platform`: the control-plane API (two or more replicas, autoscaled, disruption budget, probes on `/healthz` and `/readyz`), the background worker (one leader at a time, as the code does), the Alembic migration Job (a Helm hook before every install and upgrade), a Service, an optional Ingress, Grafana dashboards and the datasource provisioned into the org's own Grafana, and optional ServiceMonitor and NetworkPolicy. Postgres, Grafana and TokenLean are bring-your-own; the chart names Secrets, never holds secret values. TokenLean's LITE sub-chart is declared as an optional dependency (off by default) with a local placeholder until M3-04 wires the real one. A restore drill restores a logical backup of the `agentic` schema into a fresh Postgres and proves it usable (migration revision, runtime grants, every tenant's audit chain). Two runbooks: backup and restore, and upgrade.

**Architecture:**
- **Chart** `deploy/helm/agentic-platform/` (apiVersion v2). `Chart.yaml` `version` is the release version as SemVer (`0.1.0rc1` becomes `0.1.0-rc.1`) and `appVersion` the release version itself; `scripts/release.py version set` moves both and `check_versions` refuses drift (M3-21's lockstep rule).
- **Templates:** `_helpers.tpl` (names, labels, the shared env list, the pod security context), `api-deployment.yaml`, `api-hpa.yaml`, `api-pdb.yaml`, `service.yaml`, `ingress.yaml`, `worker-deployment.yaml`, `migrate-job.yaml` (hook `pre-install,pre-upgrade`, weight -5, `before-hook-creation,hook-succeeded`), `serviceaccount.yaml`, `grafana-dashboards.yaml` (one ConfigMap per file of `dashboards/*.json`, label `grafana_dashboard: "1"`, folder annotation), `grafana-datasource.yaml` (label `grafana_datasource: "1"`; the reader's password is `${AGENTIC_DASH_READER_PASSWORD}`, read from Grafana's own environment), `servicemonitor.yaml`, `networkpolicy.yaml`, `tests/test-ready.yaml` (`helm test`: the control-plane image asks `/readyz`).
- **Secrets:** `secrets.existingSecret` names one Secret (made by External Secrets, Sealed Secrets or by hand) with fixed, renameable keys: `database-url` (runtime role, API and worker), `owner-database-url` (owner role, migration Job only), optional `metrics-token`, `smtp-password`, `gateway-admin-key`. Optional keys are `optional: true` references. `values.yaml` has no field that takes a secret value.
- **Dashboards:** the chart carries a copy of `control-plane/src/agentic_cp/dashboards/grafana/*.json` in `dashboards/` (Helm reads only files inside the chart). `python -m agentic_cp dashboards --write` refreshes the copy and `--check` fails on drift, so a dashboard added to the catalog later (the ROI dashboard) reaches the chart with the command its author already runs; the template globs the folder, so no template change is needed.
- **TokenLean:** `dependencies: tokenlean-lite`, `condition: tokenlean.enabled` (default false), `repository: file://charts/tokenlean-lite`, a committed placeholder chart whose only template fails with "wired in M3-04". BYO TokenLean is `tokenlean.url` and `tokenlean.adminUrl` (`AGENTIC_CP_GATEWAY_URL`, `AGENTIC_CP_GATEWAY_ADMIN_URL`).
- **Control plane fixes for rolling upgrades (DF-413):** `/readyz` and the serve preflight treat a database revision this release does not know as newer (expand/contract migrations), so old pods stay ready while the pre-upgrade hook has migrated and during `helm rollback`; a known older revision is still `db.migrations_pending`. `migrate_async` takes a session advisory lock per schema, so two migrate runs at once serialise instead of failing.
- **Kubernetes service links (DF-415):** every pod sets `enableServiceLinks: false`.
- **Restore drill:** `agentic_cp.restore` (verification, in the image: `python -m agentic_cp db verify-restore`) checks a restored database: the revision against this release, the runtime role's grants and isolation (`enforcement_status`), and every tenant's audit chain. `scripts/restore_drill.py` restores a `pg_dump -Fc --schema=agentic` file into a fresh pinned Postgres container (or an empty database named by DSN), then runs the verification. Views are restored by the product's own DDL (`view_statements`), not from the dump, so a deployment linked to the gateway (`db link-usage`) restores without its foreign server.
- **Tool binaries:** helm 4.3.1 and kubeconform 0.8.0 run only in Linux containers: installed in `scripts/linux-check.Dockerfile` (sha256 per architecture) so `check.py --linux` runs the chart tests, and, natively, in pinned images (`alpine/helm`, `ghcr.io/yannh/kubeconform`) by digest. Without either, the tests skip with the reason; in the check image a missing binary fails. `postgresql-client` (Debian trixie, PostgreSQL 17) joins the check image for the drill's `pg_dump`/`pg_restore`.

**Tech Stack:** Helm 4 chart (apiVersion v2, works with Helm 3.8+), kubeconform, Python 3.12, existing control-plane stack (SQLAlchemy, Alembic, asyncpg), ruamel.yaml (existing) to read rendered manifests. No new Python dependency.

**Spec:** master plan "Deployment landscape" (Topology, Components, Environments, Operations, Sizing). Tracker row M3-02 and its deferred items.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Rendering, lint | Helm 4.3.1 (Apache-2.0), `alpine/helm` image (Apache-2.0 wrapper) | — |
| Schema validation | kubeconform 0.8.0 (Apache-2.0) and its schema repository | kubeval (unmaintained) |
| Dashboard and datasource loading | the k8s-sidecar label convention (`grafana_dashboard`, `grafana_datasource`; kiwigrid/k8s-sidecar, MIT) used by the Grafana chart and kube-prometheus-stack | a Grafana operator CRD (one more operator to require) |
| Template helpers | plain templates | Bitnami `common` library chart (Apache-2.0): a dependency for a few helpers, and Bitnami's catalogue changed terms in 2025 |
| Postgres HA and PITR | documented options: managed service PITR, CloudNativePG (Apache-2.0) with its `Backup`/`ScheduledBackup` and WAL archive | bundling an operator in the chart (cluster-scoped, the platform team's choice) |
| Logical backup | `pg_dump`/`pg_restore` from the pinned `postgres:17.10-alpine` image | pgBackRest/WAL-G (physical; covered by the managed service or CloudNativePG) |
| Prometheus | optional `ServiceMonitor` (prometheus-operator CRD) | bundling Prometheus (BYO, org standard) |
| Local cluster | kind (Apache-2.0), only in containers | minikube, k3d (more moving parts on Windows) |

## Global Constraints

- Windows and macOS laptops, Linux CI: tests stream files into containers with tar on stdin (no bind mounts, no path conversion), run on Docker or Podman (`CONTAINER_ENGINE`), and never run helm or kubeconform natively.
- No secret value in the chart, values or tests; fake secrets in tests are built from pieces.
- Images pinned by tag and digest, each at least two weeks old (on or before 2026-10-15).
- Cloud-agnostic: no cloud-vendor resource is required; managed Postgres is a BYO option.
- No edits to TRACKER.md, DEFERRED.md or DECISIONS-*.md; no new Alembic revision.
- ruff line length 100, no `# fmt: skip`.

## Review Focus

1. **No secret values:** nothing in `values.yaml` takes a secret; every secret is a `secretKeyRef` to `secrets.existingSecret`; the owner DSN reaches only the migration Job.
2. **Upgrade safety:** the migration hook runs before the new pods, old pods stay ready on the migrated database (DF-413), concurrent migrations serialise, `helm rollback` leaves the schema alone (expand/contract).
3. **Pod hardening:** non-root UID 10001, read-only root file system with an `emptyDir` `/tmp`, no privilege escalation, all capabilities dropped, `RuntimeDefault` seccomp, no service-account token, no service links.
4. **One active worker:** the worker's leadership is the Postgres advisory lock; extra replicas are standbys.
5. **Dashboards drift:** every file in the catalog folder is in the chart, byte for byte, and in a rendered ConfigMap.
6. **The restore drill proves something:** a broken audit chain or missing grants fail it; it never touches the source database.
7. **Cross-platform tests:** skip with a reason without a container engine; fail in the check image if a pinned binary is missing.
