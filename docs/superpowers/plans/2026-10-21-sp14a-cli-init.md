# SP14a CLI init side Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A developer can run `agentic login` and `agentic init` (org mode or `--standalone`), and a repo owner can run `agentic init --repo`. Before either init writes anything, the eight repo-root and safety checks of spec §24 run; any failure is exit 2 with nothing written. `init --repo` puts the allowed shared files on a new branch, without touching the checkout, and prints how to open the PR. Developer `init` checks prerequisites (sandbox readiness, container engine, Git Bash on Windows), caches the policy in `~/.agentic`, syncs the selected skills, fetches the org-pinned tools hash-verified from the org mirror, prepares the local index, and prints a readiness report with a fix for every failing check. It writes nothing outside `~/.agentic` and `.agentic/local`.

**Architecture:**
- **Core (`agentic`, no commons/CLI imports):**
  - `policy/model.py`: `ToolArtefact`, `ToolPin` and `OrgPolicy.tool_pins` (new policy file `tool-pins.yaml`, key `tools`), `OrgPolicy.index_export_workflow` (org.yaml; D39 opt-in export). A pin needs `tool_mirror_url`.
  - `repoconfig.py`: `RepoConfig`, the committed `.agentic/config.yaml` (classification, team, pipelines, components, codeintel adapter), `load_repo_config`, `render_repo_config`.
  - `skills/select.py`: `Selection.unknown_packs` (DF-145).
  - `sandbox/readiness.py`: the Windows guidance names the org's pinned `srt` version (DF-67).
  - `auth/credentials.py`: any keyring backend error becomes `CredentialError` (DF-157); `CI=off` is not CI and the CI error names the marker (DF-158).
- **Commons (`sdlc_commons.tool_fetch`)**: the tool fetcher over Zyroflo `tools/third_party.py` (`current_platform`, `binary_name`, `extract_binary`, `PLATFORMS`): hash-verified download from the org mirror into `~/.agentic/tools/<name>/<version>/<platform>/`, cache reuse with no network, Windows artefacts refused unless the org manifest marks them signed, `init.tool_fetched` through a `record` callback.
- **CLI (`agentic_cli`)**:
  - `repo_guard.py` (M1-50): `check_repo(cwd, mode, ...) -> RepoRoot`, raising `GuardRefusal` (a `CliError`, exit 2, `check` number 1-8).
  - `policy_source.py`: where the policy comes from: `--standalone --policy <path>`, or org mode from the user config (`policy_repo`, `org`), cloned/updated into `~/.agentic/policy/<org>/` with an expiry stamp.
  - `repo_setup.py` (M1-52): `shared_files(...)` and `commit_on_branch(...)` (git plumbing with a scratch index: the working tree and the current branch never change).
  - `readiness.py` (M1-53): `Item(name, status, detail, fix)`, prerequisite checks (python, git, sandbox, container engine + Docker Desktop licence note, Git Bash on Windows, credential), `Report`.
  - `dev_init.py` (M1-53): the developer init pipeline: policy -> skills -> tools -> index -> `.agentic/local/init.json` + init ledger events.
  - `commands/init.py`, `commands/login.py`: register `init` and `login`.
  - `wiring.py`: `StepWiring.scanner` / `scanner_for` and `ToolContext.secret_scanner` from org policy (DF-148).

**Tech Stack:** Python 3.12, Typer 0.27.3, Rich, Zyroflo `sdlc-harness` (pinned, via `sdlc_commons`), `httpx2` + `truststore` (already core deps) for the mirror download, `keyring` (already core). No new dependency.

**Spec:** §8.1, §24 (prerequisites, what init downloads, never installed, the eight checks, standalone mode), §4.2 (files in a target repo), §4.3 (policy repo), §10.3/D39 (index local; export opt-in), D33 (repo pipelines), D38 (sandbox), §13 (credentials).

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Pinned, hash-verified tool download per platform | Zyroflo `tools/third_party.py` (internal library, via `sdlc_commons.tool_fetch`): `current_platform`, `binary_name`, `extract_binary`, `PLATFORMS` | Its `cmd_fetch` is bound to Zyroflo's own `third_party/manifest.json` and prints; the orchestration (mirror URL, cache, signed rule, events) is ours, around its helpers. `pooch` (BSD-3) does hash-verified caching too but adds requests/platformdirs/packaging; the owner's own library comes first |
| OS keyring | `keyring` through `agentic.auth.Credentials` (M1-48) | - |
| HTTPS with the corporate CA store | `httpx2` + `truststore` (core deps, D36) | `urllib` ignores the OS trust store |
| Prompts | Typer/Click `prompt(hide_input=True)` and `confirm` | `questionary`: not needed for two prompts |
| Git remote URL normalising, root checks, branch commit | `git` CLI (rev-parse, hash-object, update-index, write-tree, commit-tree) | GitPython (BSD): another dependency for a handful of calls; `giturlparse` (Apache-2.0): ten lines of code |
| Skills, sandbox readiness, local index, secret scanner | `agentic.skills.sync_skills/select_skills`, `agentic.sandbox.readiness`, `agentic.codeintel.index.LocalIndex`, `SecretScanner.from_policy` | - |

## Global Constraints

- **Exit codes.** A guard refusal is `ExitCode.REFUSED` (2) with nothing written. An invalid policy, repo config or catalog is 3. A completed init that is not ready exits 1 after printing the full report. Ready is 0.
- **Nothing written outside `~/.agentic` and `<repo>/.agentic/local` by developer init**, and `git status --porcelain` is unchanged. `.agentic/local/.gitignore` (`*`) keeps the folder out of git without a committed change.
- **`init --repo` never touches the checkout**: it builds the commit with a scratch `GIT_INDEX_FILE`, `hash-object -w`, `write-tree`, `commit-tree`, and creates branch `agentic/init` (or `agentic/init-2`, ...). Files are LF. The branch adds exactly `.agentic/config.yaml`, `AGENTS.md`, `.gitattributes` (an agentic block appended to any existing file), and `.github/workflows/agentic-index-export.yml` only when `index_export_workflow` is true. Never `.agentic/pipelines/` (D33).
- **Guard comparisons** use `os.path.samefile` (same file: case, 8.3 names, symlinks and junctions all resolve) with a `realpath` + `normcase` fallback; the dangerous-location list is filesystem/drive roots and the home folder.
- **Tool fetch**: https mirror only; a checksum mismatch writes nothing; a verified cache needs no network; on `windows-*` an artefact without `signed: true` is refused and never written (the no-unsigned-binary rule); an unreachable mirror with no cache is a failed readiness item, not a crash. No fetched binary is ever executed by init or by tests.
- **Provider-agnostic**: no vendor names in flags, models or messages written by this track (the existing `srt` package name in the sandbox guidance stays).
- **Windows and macOS**: paths through `pathlib`, file locks avoided (atomic `os.replace`), git output parsed with forward slashes, `.gitattributes` written with LF.
- **Formatting, CI and records**: never `# fmt: skip`/`# fmt: off`; ruff, 100 columns; tests use `AGENTIC_HOME` and `tmp_path`; fake keys built from pieces; `uv run python scripts/check.py --all` green; TRACKER/DEFERRED/DECISIONS updated by the coordinator from this track's output.

## Review Focus

1. **Each of the eight checks refuses with exit 2 and writes nothing** (one test each; cwd in a subfolder, a junction/symlink to the root accepted, a case-changed path accepted on Windows). Tests: Task 2.
2. **A bad hash or an unsigned Windows artefact is never written; offline uses a verified cache; a changed cached binary is replaced and reported.** Tests: Task 3.
3. **`init --repo` branch contains exactly the allowed files**, the checkout and current branch are unchanged, no `.agentic/pipelines/` in org mode. Tests: Task 4.
4. **Developer init writes nothing outside `~/.agentic` and `.agentic/local`; the readiness report lists every check with a fix for each failure.** Tests: Task 5.
5. **`--install-missing` shows exactly what and asks; it installs only `on_request` pins into `~/.agentic/tools`.** Tests: Task 5.

### Task 2: Repo-root and safety guard (M1-50)
