# M3-21 Release Engineering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command, runnable on a laptop or in the org's CI, turns a clean commit into a release of the four workspace packages (agentic-core, sdlc-commons, agentic-cli, agentic-control-plane): one semver version for all four, a changelog from the commits, byte-identical wheels and sdists, a CycloneDX SBOM, generated third-party notices, signatures made with a key the org holds, an upload to the org's internal index, and a smoke install of what was published. An installed CLI (not a checkout) carries the standalone template and default library, so `agentic init --standalone` and a dry run work from the wheel alone. The upgrade and rollback runbook covers `min_cli_version` (M2-08).

**Architecture:**
- **`scripts/agentic_release/`** (a plain folder of modules beside `scripts/check.py`; imported by `scripts/release.py` and by `scripts/tests/`). It is release tooling, not a shipped package, so it may use dev-group libraries (`cryptography`, `cyclonedx-python-lib` for schema checks in tests):
  - `version.py`: the single version source (root `pyproject.toml` `[project].version`), `check_versions`, `set_version`, `bump`, `suggest_bump`.
  - `changelog.py`: conventional-commit parsing of `git log` and the Markdown section.
  - `build.py`: stage a clean export of the tracked files of each package, add the licence files and (CLI only) the framework bundle, `uv build` each, and build the git-sourced internal dependencies (Zyroflo `sdlc-harness`) from their locked commit.
  - `sbom.py`: `uv export --format cyclonedx1.5`, enriched with licences and made deterministic; the generated third-party notices; the constraints file.
  - `signing.py`: SSH signatures (the `SSHSIG` format of OpenSSH's PROTOCOL.sshsig) with an Ed25519 key, `SHA256SUMS`, verification against an `allowed_signers` file.
  - `publish.py`: `uv publish` to a configured URL with credentials from the environment; refuses public indexes and unverified artefacts.
  - `smoke.py`: a clean virtualenv, install from the index, `agentic --version`, standalone init and `agentic run --dry-run`.
- **`scripts/release.py`**: the command line (`version`, `changelog`, `build`, `sign`, `verify`, `publish`, `smoke`, `release` = all in order).
- **CLI changes:** `agentic --version`; `standalone.framework_root()` falls back to `agentic_cli/_framework/` (the bundle the release adds) when there is no checkout; `dev_init.BUNDLED_SKILLS` uses the same root.
- **Templates:** `templates/release/release.yml`, a GitHub Actions workflow the org can adopt (actions pinned by commit SHA, gitleaks over the full history); the shipped workflow templates pinned by SHA too (DF-689).
- **Docs:** `docs/runbooks/release.md` (cut a release, key management, publish, upgrade, rollback, `min_cli_version`).

**Tech Stack:** Python 3.12, uv 0.12.1 (`uv build`, `uv export --format cyclonedx1.5`, `uv publish`, `uv venv`, `uv pip`), `cryptography` 50.0.2 (Apache-2.0 OR BSD-3-Clause, already locked through the dev group), `cyclonedx-python-lib` 11.12.0 (Apache-2.0, already locked through pip-audit) for SBOM schema validation in tests. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-16-agentic-sdlc-design.md` (supply chain, CLI distribution through the internal index, `min_cli_version`). Master plan row M3-21; M2-08 (minimum CLI version).

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Wheel and sdist builds | `uv build` with the `uv_build` backend already used by every package: rebuilds are byte-identical (fixed timestamps, sorted entries), checked by a test | hatch/setuptools: a second build backend |
| SBOM | `uv export --format cyclonedx1.5` (uv itself), enriched with licences from `scripts/licence_check.py` | cyclonedx-bom (`cyclonedx-py`): reads environments or requirements files, not `uv.lock`; a new dependency |
| SBOM validation | `cyclonedx-python-lib` `JsonStrictValidator` (already locked) | — |
| Third-party notices | `licence_check._licence_of` and the exceptions file, plus each installed distribution's licence files | pip-licenses (MIT): reads the installed environment only, not the shipped set from the lock; a new dependency |
| Signing | SSH signatures (`ssh-keygen -Y sign/verify` format) made with `cryptography` Ed25519; verifiable with stock OpenSSH on Windows, macOS and Linux | Sigstore/cosign keyless: needs OIDC plus Fulcio/Rekor (the public log would record every internal release, or the org runs its own Sigstore); cosign and minisign are native binaries; GPG is heavy and unfriendly on Windows |
| Publishing | `uv publish` (legacy upload API, any index: devpi, Artifactory, Nexus, pypiserver, GitLab) | twine: a new dependency doing the same |
| Test index | a small in-test HTTP server (legacy upload + PEP 503 simple pages) | pypiserver: zlib/libpng licence, not on the allow-list; devpi-server: heavy (argon2-cffi native, a separate process and init) |
| Changelog and version bumps | ~150 lines over `git log` and the pyproject files | git-cliff: native binary; commitizen, python-semantic-release (MIT): heavy, interactive dependencies, impose their own config and tagging flow; `uv version`: one package at a time and does not move internal pins |

## Global Constraints

- **One version, lockstep.** The root `pyproject.toml` `[project].version` is the source. Every member's `version` and every internal requirement (`agentic-core`, `sdlc-commons` in the CLI and control plane) equal it exactly (`==X.Y.Z`), so a published CLI can never resolve another release's core. The git-sourced `sdlc-harness` requirement is pinned to its locked version. `release.py version --check` (run by `build`) fails on any drift. Versions are `MAJOR.MINOR.PATCH` with an optional `aN`/`bN`/`rcN`, so they match core's `MIN_VERSION_PATTERN` (an org can set `min_cli_version` to any release). `--set` refuses a version that is not greater than the current one.
- **Builds come from git.** The staged tree holds only tracked files (`git ls-files`), with LF line endings (`.gitattributes eol=lf`), so a Windows and a Linux build of one commit give the same bytes. A real release refuses a dirty tree; `--allow-dirty` exists for tests and dry runs and is written into `release.json`.
- **Never a public index.** `publish` refuses `pypi.org`, `test.pypi.org` and `files.pythonhosted.org` hosts. Credentials reach `uv publish` only through `UV_PUBLISH_USERNAME`/`UV_PUBLISH_PASSWORD`/`UV_PUBLISH_TOKEN`, never argv. Trusted publishing is off.
- **Verify before publish.** `publish` verifies every artefact's signature and `SHA256SUMS` against the given `allowed_signers` and identity first.
- **Tests never call a live service.** No PyPI, no signing service, no GitHub: keys are generated per test, the index is a local server, third-party wheels come from uv's cache through `uv.lock` (`--offline`).
- **Cross-platform.** Paths through `pathlib`; subprocesses with argument lists; the venv's executables under `Scripts/` on Windows and `bin/` elsewhere.
- **Formatting, CI and records:** never add `# fmt: skip` or `# fmt: off`; line length 100; check pytest's exit code directly; `uv run python scripts/check.py --all` green on Windows and Linux; TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.

## Review Focus

1. **Byte-identical rebuilds, and only committed content.** Two builds of one tree give identical wheels, sdists and SBOM; an untracked file in a package folder never reaches a wheel. Test: Task 4 `test_two_builds_are_byte_identical`, `test_untracked_files_are_not_shipped`.
2. **A tampered artefact, a wrong key, identity or namespace** fails verification, and `publish` refuses before uploading anything. Our signatures verify with stock `ssh-keygen -Y verify`. Test: Task 7 `test_tampered_file_fails`, `test_wrong_identity_or_namespace_fails`, `test_ssh_keygen_verifies_our_signature`; Task 8 `test_publish_refuses_unverified_artefacts`.
3. **Publishing never reaches a public index and never shows a credential.** Test: Task 8 `test_public_index_refused`, `test_credentials_only_in_the_environment`.
4. **An installed CLI with no checkout** finds the bundled template and library; a checkout still uses its own; `AGENTIC_FRAMEWORK_ROOT` overrides both. The end-to-end test installs the published wheels from the local index into a clean venv and runs `agentic --version`, `init --standalone` and `run --dry-run`. Test: Task 4 `test_framework_root_prefers_env_then_checkout_then_bundle`; Task 9 `test_published_release_installs_and_dry_runs`.
5. **Version drift and dependency confusion.** A member version or internal pin that disagrees, an unpinned `sdlc-harness`, or a downgrade is refused. Test: Task 1 `test_check_reports_every_drift`, `test_set_refuses_a_downgrade`.
