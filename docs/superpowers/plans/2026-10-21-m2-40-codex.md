# M2-40 Codex Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent steps can run on the `codex` backend. It drives the pinned `codex exec` CLI (rust-v0.160.1, Apache-2.0, spike S3) under the S3 lock-down:
- a per-step `CODEX_HOME` config, with the same lock-down keys also passed as `-c` overrides;
- the worktree marked `trust_level = "untrusted"` (mandatory, contract-tested);
- plugins, analytics, feedback, OTel, history and web search off;
- srt as the outer sandbox, with Codex's own sandbox in `danger-full-access`;
- the shell policy compiled to execpolicy (`deny` -> `forbidden`, `ask` -> `prompt`, refused under `never`; `allow` -> `allow` only when srt is the boundary);
- the answer shaped by `--output-schema`;
- the step charged from `turn.completed.usage` at policy prices (`estimated`).

The capability matrix gains a `codex` row and a new flag, "no shell default-deny", which `OrgPolicy.unhonoured` acts on. An org model catalog (`model_catalog_json`) gives every model, whatever its vendor, `apply_patch`, and lets the step's tool surface follow its capabilities (DF-115). A PreToolUse hook enforces the commons guard (deny rules, allow-list default-deny, redirect-aware splitting) inside Codex (DF-116).

**Architecture:**
- **`agentic.backends.capabilities`** (modified):
  - `BackendCapabilities.shell_default_deny: bool = True`;
  - the `codex` row;
  - `backend_issues` reports `shell_default_deny` through `OrgPolicy.unhonoured`, whose new key defaults to `warn`.
- **`agentic.backends.codex_rules`** (new, pure): `ShellRules(allow, ask, deny)` and `compile_rules(rules, *, srt_boundary) -> str`. Each rule becomes a Starlark `prefix_rule`. `a|b` alternatives become pattern alternative lists. Every rule carries a `match` example, because Codex validates examples at load.
- **`agentic.backends.codex_catalog`** (new, pure, DF-115): `catalog_entry(model, *, tools, effort, instructions, overrides)` and `model_catalog(...) -> dict`, a one-model `ModelsResponse` for the step's resolved model:
  - `apply_patch_tool_type = "freeform"` only when the agent has `edit_files`;
  - `shell_type = "disabled"` when the agent has no shell-mapped capability;
  - the framework's base instructions template, from package data.
- **`agentic.backends.codex`** (new; needs the `codex` extra, `tomli-w`):
  - `CodexSettings`;
  - `lock_down(step, ...) -> CodexLaunch`, which holds the argv, the env, and the files to write (`config.toml`, `rules/agentic.rules`, `models.json`, `schema.json`);
  - the JSONL event reader;
  - `CodexRunner` (an `AgentRunner`);
  - `CodexBackend`;
  - `check_version`.
- **`agentic.backends.codex_hooks`** (new, pure, DF-116): the `[hooks]` table for a PreToolUse command handler, and the `trusted_hash` Codex computes for it (sha256 over canonical JSON of the normalised hook identity, from codex-rs `hooks/src/engine/discovery.rs` and `config/src/fingerprint.rs` at the pinned tag).
- **`sdlc_commons.codex_hook`** (new): `python -m sdlc_commons.codex_hook <guard.json>`. It reads Codex's PreToolUse JSON on stdin, builds the `Guard` from the spec file and answers `{"decision": "block", "reason": ...}` for a refused `Bash` command. An ask-listed command is refused too, because no person is there to approve it.
- **Install** (decided): an optional extra `codex` of agentic-core (`tomli-w`, pure Python, MIT) plus the pinned **external** Codex CLI found on PATH. Its version is checked before a run (`codex --version` must say 0.160.1). It runs on macOS and Linux, and on Windows inside WSL2 (D38): native Windows is refused, so the npm win32 package and its unsigned `rg.exe` are never used. `backends.available()` reports `codex` when the extra is importable, `codex` is on PATH, and the OS is not native Windows.
- **Contract tests:** the real pinned binary, only where `codex --version` reports the pin. In practice that is the Linux check container, whose Dockerfile installs it by sha256 for amd64 and arm64. They run against `responses_stub.py`, grown from `spikes/s3_codex/stub.py`. Elsewhere they are skipped, with the reason given. Unit tests run everywhere.
- **Not in this row:** CLI wiring (`CONFIGURED_BACKENDS`, srt `wrap_for`, `Guard` spec), as for claude-code (DF-212 -> M2-41). TokenLean's real `/v1/responses` (ST-4, M2-32).

**Tech Stack:** Python 3.12. `tomli-w==1.2.0` (MIT, released 2025-01-15, already locked through pip-audit) as the extra `codex`. Codex CLI rust-v0.160.1 (released 2026-10-05; Linux musl tarballs: amd64 sha256 `9226581b…`, arm64 sha256 `f54dc585…`). pytest.

**Spec:** §9.1 backends, D42, §shell policy; S3 record decisions 2-6; DECISIONS-overnight 21-24.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Driving Codex | the `codex exec` CLI itself (Apache-2.0), pinned | an SDK: Codex's TypeScript SDK wraps the same CLI; no Python SDK is published by the vendor |
| TOML writing | `tomli-w` 1.2.0 (MIT) | a hand-rolled emitter |
| Stub Responses server | `spikes/s3_codex/stub.py` (ours) | — |
| Guard semantics in the hook | `sdlc_commons.guards.Guard` (Zyroflo walls + framework floor) | a second matcher in core |
| Process-tree kill | `agentic.backends.claude_code._descendants` | — |

## Global Constraints

- Core never imports `sdlc_commons`, `agentic_cli` or Zyroflo. `tomli_w` is imported only in `agentic.backends.codex`, which has an import-linter contract.
- No vendor names in the engine, policy model or protocols. Vendor strings (`exec_command`, `apply_patch`) live only as matrix data and in the codex modules.
- Paths are written as POSIX text for Codex (it runs on POSIX only). TOML and JSON are written with LF line endings.
- Never `# fmt: skip`. Line length 100. Fake keys are built from pieces.
- TRACKER.md, DEFERRED.md and DECISIONS-*.md are not edited. Notes go in the structured output.

## Review Focus

1. **A hostile repo's `.codex/`** (`developer_instructions`, an `[mcp_servers]` entry, a rules file that allows `git push`, a hook) never takes effect. Test: `test_codex_contract.py::test_a_hostile_repo_config_never_loads` and the unit test `test_untrusted_project_entry_is_always_written`.
2. **No unsandboxed codex.** Without a sandbox wrap the runner refuses, unless the settings explicitly say `require_sandbox=False` (tests only). `allow` rules are emitted only when srt is the boundary. Test: `test_codex_lockdown.py::test_runner_refuses_without_a_sandbox`, `test_codex_rules.py::test_allow_rules_only_under_srt`.
3. **`deny` -> `forbidden` holds, and the redirect bypass is closed by the hook guard.** Test: contract `test_a_denied_command_is_forbidden`, `test_the_hook_guard_blocks_a_redirect_chain_and_unlisted_commands`.
4. **The cost** is charged from `turn.completed.usage` at policy prices, marked `estimated`, never from TokenLean's header. Past the slice it raises `LimitHit`. Test: `test_codex_events.py`, contract `test_usage_is_charged_from_turn_usage`.
5. **The provider-agnostic matrix:** `shell_default_deny` reaches policy as ignore/warn/block. Test: `test_capabilities.py`.
