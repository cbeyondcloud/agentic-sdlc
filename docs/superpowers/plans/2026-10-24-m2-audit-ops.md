# M2 Audit and Operations Implementation Plan (track m2-audit-ops)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auditors can prove the record has not been changed. `agentic audit verify` checks every local run ledger (Zyroflo's chain, through `sdlc_commons`) and the control plane's per-tenant audit chain, and names the run or record, the entry and the class of change of anything tampered with. `agentic audit export --team --from --to` streams the tenant's audit records as JSONL or CSV with a chain proof that a small stdlib-only verifier checks without our database. The control plane gains Prometheus metrics, alert rules checked by `promtool`, and auto-trip: a team whose spend rate or error rate passes a policy threshold is paused, its leads are mailed and the trip is audited, with hysteresis and reset rules.

**Rows:** M2-26, M2-13, M2-12, M2-11, plus every Open deferred item that targets them (DF-292, DF-309, DF-406, DF-410, DF-485, DF-486, DF-495, DF-500, DF-502, DF-565).

**Architecture:**

- **`agentic.auditproof` (core, stdlib only).** One module that an auditor can copy and run on its own (`python auditproof.py export.jsonl`). It holds:
  - the chain hash formula (sha256 over canonical JSON of every field but `hash` and `signature`), byte-identical to Zyroflo's `approve.entry_hash`, which `sdlc_commons.ledger.entry_hash` wraps (a parity test pins this);
  - `ChainChecker`, a streaming checker that locates each problem (position, seq) and classifies it: `content`, `hash`, `link`, `sequence`, `unreadable`;
  - the export format (JSONL rows `header` / `entry` / `link` / `proof`, CSV columns), the spreadsheet-safe CSV cell escaping and its exact inverse;
  - `verify_export(path)`.
  Core imports nothing outside the standard library here (an AST test enforces it), so the CLI, the control plane and an auditor all run the same code.
- **CLI `agentic audit` group** (`cli/src/agentic_cli/commands/audit.py`, logic in `cli/src/agentic_cli/audit.py`):
  - `verify [RUN_ID...] [--control-plane] [--export FILE]`. Local runs are checked with `RunLedger.verify()` (Zyroflo, authoritative) plus `ChainChecker` (location and class). The control-plane chain is pulled page by page from `GET /v1/audit` and checked locally, so the verdict does not trust the server's own check. Exit 0 when intact, 3 when a chain does not verify, 1 when something could not be read, 2 when refused.
  - `export --team T --from D --to D [--format jsonl|csv] [--output FILE]` streams the export to a file and verifies it before reporting the anchors.
- **Control plane, audit export** (`agentic_cp/audit/export.py`, route `GET /v1/audit/export`). A new permission `audit.export` (catalogue kind `team`) is seeded to the builtin `auditor` role (and `org-admin`, which holds every permission). A team lead's `audit.read.team` does not grant it. The route checks the permission, appends `audit.exported` to the chain and commits. Then a `StreamingResponse` reads the range through a server-side cursor in its own tenant transaction. Within a team export, the other teams' and org-level records in the range travel as `link` rows (seq, prev, hash only), so the chain stays continuous without disclosing them.
- **Control plane, metrics** (`agentic_cp/metrics.py`, pure ASGI middleware, `GET /metrics`). Each app has its own `prometheus_client.CollectorRegistry`. The metrics are:
  - request counts by route template and status class, and request duration;
  - ingest lag (event `at` to receipt), ingest results and rejections by code;
  - kill-switch state reads;
  - per-tenant gauges read from the database at most every `metrics_refresh_seconds`: outbox pending, failed and oldest pending; active switches by mode and source (`human` or `auto-trip`). Tenants beyond `metrics_max_tenants` fold into `tenant="_other"`, so cardinality stays bounded.
  `/metrics` needs `AGENTIC_CP_METRICS_TOKEN` as a bearer token; without one it answers 404. The alert rules in `control-plane/deploy/prometheus/alerts.yml` are checked by `promtool check rules` in the Linux check stage: Prometheus 3.15.0's promtool is pinned by sha256 in the check image, never installed on a laptop.
- **Control plane, auto-trip** (`agentic_cp/alerts/autotrip.py`, a worker job):
  - **Policy.** Org policy `org.yaml: auto_trip` (thresholds, window, minimum steps, reset ratio, hold time, auto-clear). A team may only tighten the thresholds (`teams/<team>.yaml: auto_trip`). The settings are stored with each accepted version (`run_settings`).
  - **Measure.** Per team over the window: measured spend per hour (the sum of `step_finished` `cost.usd` received in the window; `None` when no step reported a cost, never 0), and the error rate (outcome `error` over `step_finished`; `None` below `min_steps`).
  - **State machine.** Per (team, kind) in a new tenant table `auto_trips`: `armed -> tripped` above the threshold. Reset is one of two paths. With `auto_clear`, the switch clears below `threshold x reset_ratio` once tripped for `hold_minutes`. Otherwise the state moves `tripped -> disarmed` when a person clears the switch, and back to `armed` only once the value has fallen below the reset level. That is the hysteresis.
  - **A trip** inserts a team pause switch (the existing `kill_switches` table, `reason` "auto-trip: ...", `created_by` `system:auto-trip`) through the same helper the API uses (`killswitch.set` audited). It queues a mail to the team's `killswitch.team` holders (the existing outbox) and appends `autotrip.tripped`, all in one transaction.
- **Hardening from the deferred register:**
  - the worker refuses an unenforced database like `serve` does (DF-495);
  - an in-process per-principal token bucket is on by default (DF-309);
  - a README section covers anonymous git and the operational settings (DF-500, DF-410 ingress note).

**Tech Stack:** Python 3.12; `prometheus-client==0.26.0` (Apache-2.0 / BSD-2-Clause, pure Python, no dependencies, released 2026-07-24) in the control plane's dependencies only (an import contract keeps it out of core, commons and the CLI); Prometheus 3.15.0 `promtool` (Apache-2.0, released 2026-09-25) in the Linux check image only. Everything else reuses what is locked.

**Spec:** §14.3 (metrics: bounded labels only), §14.5 (audit fields, two chains), §8.6 (kill switch scopes and audit), §22 deployment table (alert/auto-trip jobs as workers), §16 operations (health metrics and alert rules). Master plan rows M2-11, M2-12, M2-13, M2-26.

## OSS reuse decisions

| Need | Reused | Not reused, why |
|---|---|---|
| Chain hash and run-ledger checks | Zyroflo through `sdlc_commons.ledger` (`RunLedger.verify`, `entry_hash`) for every local verdict | - |
| Independent export verifier | Python stdlib (`hashlib`, `json`, `csv`) re-implementing Zyroflo's one-line formula, pinned to it by a parity test | importing Zyroflo or our packages: an auditor must verify without our code or database (the point of the proof); Trillian/immudb (Apache-2.0) are whole servers with their own log format |
| Prometheus exposition | `prometheus-client` 0.26.0 (Apache-2.0), with a per-app `CollectorRegistry` | `prometheus-fastapi-instrumentator` (ISC) and `starlette-exporter` (Apache-2.0): both register on the global registry by default and are unverified with our pinned Starlette 1.7; the middleware we need is about 40 lines of pure ASGI that leaves streaming responses alone |
| Rule validation | `promtool check rules` from the pinned Prometheus release, in the Linux check image | Python YAML checks alone: they cannot validate PromQL |
| CSV formula-injection defence | OWASP's leading-character rule, done by hand (10 lines) | `defusedcsv` (Apache-2.0): its escaping cannot be undone exactly, so the verifier could not recompute hashes from a CSV export |
| Rate limiting | a small keyed token bucket behind the existing `RateLimiter` hook | `limits` (MIT): pulls `deprecated`/`wrapt` (a native extension); `aiolimiter` (MIT): one limiter, not keyed buckets with eviction |

## Global Constraints

- **Tenancy as built.**
  - Every new table is tenant-owned under forced RLS (`enable_tenant_rls`), listed in `TENANT_TABLES`, and has an isolation row factory.
  - Every new `/v1` route has an `EndpointCase`. Another tenant's objects answer exactly like missing ones.
  - Every change appends to the tenant's audit chain in the same transaction.
  - The runtime role keeps no `BYPASSRLS`.
- **Migration.** One revision, `0011_audit_ops`, revising `0010`. Other tracks may add revisions too; the coordinator re-parents heads at merge. Metadata in `tables.py` matches it exactly (`test_migrations_match_metadata`).
- **Provider-agnostic.** No vendor names in code, flags or protocols. Spend is whatever `cost.usd` the run reported.
- **Unmeasured is null.** Spend with no reported cost is `None`, never 0. An error rate below `min_steps` is `None`. `None` never trips.
- **Cardinality.** Prometheus labels are route templates, methods, status classes, bounded code sets and tenant slugs capped by `metrics_max_tenants`. Never run, user, team or token ids.
- **CSV cells.** A cell that starts with `= + - @`, tab, carriage return, the full-width forms of `= + - @`, or `'` gets one leading `'`. A verifier strips exactly one leading `'`. The escape is exact both ways.
- **Windows and macOS.** Exports are written as UTF-8 bytes with `\n` line ends (CSV with `\r\n` as RFC 4180 says) on every OS. File paths use `pathlib`. No native binary runs on the host: promtool runs only in the Linux check container.
- **Never `# fmt: skip`**; ruff line length 100. Check pytest exit codes directly. Run the full `scripts/check.py --all` before returning.
- **Records.** TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's structured output.

## Review Focus

1. **A tampered entry is detected and located.** Each case gives the run or record, the entry and the class:
   - a local `events.jsonl` line whose contents were edited (`content`);
   - one whose recorded hash was rewritten (`hash`);
   - a removed line (`sequence` + `link`);
   - a tampered approvals entry;
   - a control-plane record edited by a superuser (`content` at its seq).
   Exit code 3. Tests: Task 2 `test_edited_event_is_located_as_content`, `test_rewritten_hash_is_located_as_hash`, `test_removed_event_is_located`, Task 3 `test_tampered_control_plane_record_is_located`.
2. **The export verifies independently.** The stdlib verifier, run as a copied file in a subprocess with `-I` (isolated mode, so our packages cannot be imported), accepts an export straight from the server and rejects:
   - one edited byte (`content`);
   - a dropped row (`link`);
   - a truncated stream with no proof line.
   A team export carries other teams' records only as `link` rows. Tests: Task 1 `test_verifier_runs_standalone`, Task 4 `test_team_export_hides_other_teams`, `test_export_verifies_independently`.
3. **Only auditors export.** An auditor (org scope) and an org admin may export. A team lead (who holds `audit.read.team`) and a developer get 403. Another tenant's records never appear. Every export is itself audited (`audit.exported`). Tests: Task 4 `test_only_auditors_export`, isolation case.
4. **CSV is safe in a spreadsheet and still verifiable.** A record whose reason is `=HYPERLINK(...)` or `@SUM(...)` is exported with a leading `'`, and the verifier still recomputes its hash. Test: Task 1 `test_csv_cells_are_formula_safe_and_reversible`, Task 4 `test_csv_export_is_formula_safe`.
5. **Auto-trip neither flaps nor trips on silence.** A spend series oscillating around the threshold trips once, then holds. It resets only below the reset level, and after the hold time when auto-clear is on. A team with no measured cost never trips on spend. Trip and reset each audit, and a trip queues one mail. Tests: Task 8 `test_oscillating_series_trips_once`, `test_unmeasured_spend_never_trips`, `test_trip_pauses_team_mails_and_audits`.
6. **Metrics stay bounded and private.** `/metrics` answers 404 without a configured token and 401 for a wrong one. An unmatched path is labelled `<unmatched>`, not by its raw path. Tenants beyond the cap fold into `_other`. Tests: Task 6.

**Interfaces:**
- `entry_hash(entry: Mapping) -> str`: `"sha256:" + sha256(json.dumps(body, sort_keys=True, separators=(",", ":"), ensure_ascii=False))`, where `body` is every field but `hash` and `signature`.
- `Finding(position: int, seq: int | None, field_class: str, detail: str)`. The classes are `content`, `hash`, `link`, `sequence`, `unreadable`, `anchor`, `scope`, `format`.
- `ChainChecker(first_seq: int | None = 1, prev: str = "")`:
  - `feed(entry: Mapping | None, *, opaque: bool = False)`;
  - `finish() -> list[Finding]`;
  - `last: tuple[int | None, str]`.
  It buffers one entry, so a hash mismatch can be classified. When the next entry's `prev` equals the recomputed hash, the class is `hash` (the recorded hash was replaced, contents intact). Otherwise it is `content`.
- `check_chain(entries, **kw) -> list[Finding]`.
- `EXPORT_FORMAT = "agentic-audit-export/1"`, `RECORD_FIELDS` (the 16 fields), `CSV_COLUMNS = ("kind", *RECORD_FIELDS)`.
- `csv_cell(value) -> str` / `csv_value(cell, field) -> object` (inverse).
- `ExportReport(ok, format, entries, links, start, end, head, team, findings)`.
- `verify_export(path: Path) -> ExportReport`.
- `main(argv) -> int`: exit 0 when intact, 3 when broken, 64 on wrong usage.
