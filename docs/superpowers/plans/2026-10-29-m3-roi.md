# M3 Executive ROI Implementation Plan (M3-01)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An executive sees total AI cost broken into the six drivers of the master plan's "Executive cost breakdown" (users x sessions per user x turns per session x requests per turn x tokens per request x cost per token), for the whole org and for each user, filtered by team, pipeline, agent and month, reconciled against the gateway's actual cost, with untagged calls on their own "unattributed" line. Next to it: the ROI measures the records can already answer (human wait at gates, step rework rate, monthly cost per team), the ones they cannot yet (PR and deployment measures, gateway savings) shown as NULL with a reason, never 0. Finance gets a monthly chargeback CSV per team (a control-plane route with RBAC and audit, and `agentic report chargeback`) whose totals equal the SQL totals.

**Architecture:**
- **Views (`agentic_cp.dashboards.views`).** New tenant-scoped `dash_*` views, all reading through `dash_scope` like the M2-37 set:
  - `dash_cost_runs`: one row per registered run: its month (UTC month of `opened_at`), owner (users.email), team, pipeline (`runs.pipeline`, else the run's pipeline tag).
  - `dash_cost_calls`: one row per gateway call with the attribution every cost view uses: `attributed` (the call's run tag names a registered run), `unattributed_reason` (`no run tag` / `run not registered`), month (the run's month, else the call's own), user, team (the run's, else the authenticated team), pipeline, step, agent (ledger, else the step's first tagged agent), model (routed, else requested), the four token counts, `tokens` (sum of the parts the gateway measured; NULL when none) and cost.
  - `dash_cost_facts`: the filterable layer: one row per (registered run, step) with `executions` (ingested `step_started` events: every loop iteration and retry counts), calls, tokens and cost; a run with no step and no call keeps one row; unattributed calls are grouped rows with `attributed = false`.
  - `dash_cost_drivers` (org, per month), `dash_cost_drivers_team` (per month and team), `dash_cost_drivers_user` (per month and user): the six factors, `product_usd`, `actual_usd` (attributed), `unattributed_usd`, `total_usd`, `diff_pct` and `data_quality_alert` (difference above 0.5 %, or a NULL factor under a measured cost).
  - `dash_chargeback`: per month and team: users, runs, step executions, calls, tokens (split), attributed, unattributed and total cost.
  - `dash_roi_month`: per month and team: runs, users, step executions and repeats, step rework rate, gate decisions, human wait at gates, total cost, and the not-yet-measured ROI columns (NULL).
  - One SQL generator, `driver_sql(where, group)`, writes the factor arithmetic for the views and for every filtered Grafana panel, so the formula exists once.
- **Migration `m3_01_roi`** (after `m3_07_run_health`): `runs.pipeline` (nullable text, written at registration); creates the new views only (the M2-37 views and the linked contract views are not touched); grants SELECT on them to every reader already bound (`tenants.dashboard_role`). `DASH_VIEWS` becomes `M2_37_VIEWS + ROI_VIEWS`; the M2-37 migration creates `M2_37_VIEWS` explicitly.
- **DF-631.** `link.relink_contracts` re-points the contract views at an existing link schema (no password needed: the foreign server and user mapping persist). `migrate` runs it after every upgrade, so a future migration that recreates the views no longer leaves dashboards on placeholders. `/readyz` reports `gateway_linked`.
- **Grafana.** An eighth dashboard, "Agentic - Executive ROI" (`agentic-executive-roi`), rendered from `catalog.py` and provisioned with the others: variables month, team, pipeline, agent (multi, All) and a "what-if users" textbox (default 1000); stat tiles for the factors, actual cost, product of factors, unattributed cost, reconciliation difference and cached-token share; a month-over-month table attributing the change to each factor (LMDI); the per-user table (Grafana tables sort by any column); a what-if projection (target users x the per-user median of every other factor); the per-model split of cost per token; monthly cost per team; the ROI measures table with value and reason.
- **Chargeback.** `GET /v1/cost/chargeback?month=YYYY-MM&team=..&format=json|csv` (default month: the previous calendar month, UTC). Whole org needs `dashboard.view.org` (the `exec-viewer` and `auditor` roles have it); one team needs `dashboard.view.team` there. Every export is audited (`cost.chargeback_exported`). The runtime role may SELECT `dash_chargeback` (`db_roles.RUNTIME_VIEWS`, granted by `grant_runtime`). Wire models and the CSV writer live in `agentic.orgapi.cost`, so the server's CSV and the CLI's file are byte-identical.
- **CLI.** A new `report` group: `agentic report chargeback [--month YYYY-MM] [--team T] [--output FILE]` writes the CSV atomically (never over an existing file) and prints the totals; `--json` prints the report.

**Tech Stack:** PostgreSQL views (existing), Grafana file provisioning (existing), FastAPI + SQLAlchemy Core + Alembic (existing), stdlib `csv` and `decimal`. No new dependency.

**Spec:** master plan "Executive cost breakdown" and row M3-01; spec §14.4 (dashboards). Deferred register: DF-629 (dashboard coverage gaps, cost per accepted change), DF-631 (view migration resets the contract views).

## Global Constraints

- **NULL is unmeasured, never 0** (Zyroflo metrics doctrine). A sum over no call is NULL; a ratio with a zero or NULL denominator is NULL; the ROI measures without a source are NULL columns and the dashboard says why.
- **Every factor is a ratio of measured totals of the same slice**, so `product_usd` equals `actual_usd` up to numeric rounding (Postgres numeric keeps at least 16 significant digits). The reconciliation compares the product with `total_usd`, which includes the unattributed cost, and raises `data_quality_alert` above 0.5 %.
- **Unattributed is a line, never hidden**: calls without a run tag, and calls tagged with a run the control plane does not know, are `attributed = false` rows in every cost view, with their reason.
- **One attribution rule everywhere**: the drivers, the chargeback, the dashboard and the CSV all read `dash_cost_calls` / `dash_cost_facts`, so their totals agree by construction.
- **Readers read views only.** A reader role may SELECT the `dash_*` views and nothing else; the new views are covered by the generated isolation tests (`DASH_VIEWS`). The runtime role gains SELECT on `dash_chargeback` only.
- **No vendor names** in titles, views, columns, routes or CLI flags.
- **No live model, provider, gateway or GitHub calls in tests** (owner decision 73): seeded Postgres only.
- **Formatting, CI and records:** never add `# fmt: skip` / `# fmt: off`; line length 100; check pytest's exit code directly; `uv run python scripts/check.py --all` green on Windows and Linux; TRACKER.md, DEFERRED.md and DECISIONS are updated by the coordinator from this track's output.

## Rulings (for owner review)

| # | Problem | Alternatives | Decision | Why |
|---|---|---|---|---|
| R1 | Which month a run's cost belongs to | call month; run month | the run's month (UTC `opened_at`) for a registered run's calls; the call's own month for unattributed calls | every factor of a slice then counts the same runs, so no month has calls without runs (a NULL factor at every month boundary); a run lasts minutes to hours, so the shift is small and totals over months are unchanged |
| R2 | DORA through Zyroflo `metrics.dora` | import via `sdlc_commons`; compute in SQL | SQL, with Zyroflo's definitions: lead time and change-failure rate are NULL with "no deployment is recorded" | the control plane may import `sdlc_commons`, but `metrics.dora` reads Zyroflo's file run state in a repository, and Grafana reads SQL |
| R3 | PR measures (cost per accepted change, request-to-merged-PR cycle time, merge rate) | invent a proxy; defer | NULL columns now; deferred with a new DF item | no PR outcome reaches the control plane: `agentic pr open` writes a local record and nobody reads the merge |
| R4 | Where the chargeback command lives | `agentic cost chargeback`; new group | new `report` group | `agentic cost <run>` takes a positional run id, so a subcommand would collide with a run named `chargeback` |
| R5 | How the migration adds views | drop and recreate all; additive | additive, plus grants to bound readers | recreating resets the linked contract views and drops every reader's grants |
| R6 | Tokens when the gateway lacks a count | treat as 0; NULL the call | the sum of the parts it measured; NULL only when none | the cache counts are optional in the contract; the factors still telescope because the same token total is used in both ratios |
| R7 | "Rework rate" without deployments | DORA rework (unplanned deploys); step repeats | "step rework rate": repeated executions of a step in the same run / step executions | measurable now and named for what it measures (Zyroflo: never rename a proxy after a different subject) |
| R8 | Gateway savings | read `baseline_tokens`; NULL | NULL with "optimisations are off (ST-7 opt-in)" | the owner asked for NULL while optimisations are off; wiring the baseline is deferred to M3-24 |
| R9 | Default chargeback month | required; current; previous | the previous calendar month (UTC) | chargeback is run after the month closes |
| R10 | A run's pipeline | call tag only; store at registration | `runs.pipeline` at registration, else the run's pipeline tag | a run with no call (or untagged calls) still filters by pipeline |
| R11 | What-if projection | product of medians; median of products | target users x the per-user median of each other factor | the master plan's wording: "everything else at current median" |

## Review Focus

1. **Reconciliation.** The product of the six factors equals the attributed actual cost within 0.5 % for the org, every team and every user on seeded data; the org line's `total_usd` equals the gateway total and the alert fires when untagged calls exceed 0.5 %. Tests: `test_product_of_factors_equals_actual_cost_for_org_and_each_user`, `test_untagged_calls_raise_the_org_alert`.
2. **NULL not 0.** A slice with runs but no calls has NULL cost factors; a gateway without cache columns gives a NULL cached share; the ROI columns without a source are NULL. Tests: `test_unmeasured_factors_are_null_not_zero`, `test_cached_share_is_null_without_cache_counts`.
3. **Unattributed is visible.** Calls without a run tag and calls of unregistered runs are `attributed = false` with their reason in `dash_cost_calls`, `dash_cost_facts` and the chargeback. Test: `test_untagged_calls_appear_as_unattributed`.
4. **Chargeback.** The CSV's per-team sums equal `dash_chargeback` and the gateway total; RBAC refuses a developer, allows exec-viewer (org) and a team lead (own team only); every export is on the audit chain; another tenant's team never appears. Tests: Task 5.
5. **Upgrade safety (DF-631).** Migrating keeps a linked gateway linked, and bound readers can read the new views without re-binding. Tests: `test_migrate_relinks_reset_contract_views`, `test_bound_reader_reads_new_views_after_upgrade`.
